# 5.G5 GPU 服务器阶段门指南

本指南只适用于新的自包含 Agent-Qwen 拓扑。旧的独立 Ollama Compose、宿主模型目录和
`server_validate_trace_workspace.sh` 不能用于通过 5.G5。

## 本机准备结果

默认离线包位于 `D:\hxjh\trace-g-server-kit-g5`。包中只包含：

- 锁定的自包含 Agent-Qwen 镜像；
- 锁定的 Controller 镜像；
- 当前源码、G5 staging/验收/验证脚本；
- G4 权威通过证据；
- `g5-server-kit-lock.json` 和顶层 `SHA256SUMS`。

包中不得出现独立 Ollama 镜像、外置 Qwen 模型归档或宿主模型挂载配置。

本机重新制作：

```powershell
cd D:\hxjh\wp2-redteam
.\scripts\prepare_g5_server_kit.ps1
```

上传使用既有逐文件断点续传程序，但必须显式指定新包：

```powershell
.\scripts\upload_server_kit.ps1 `
  -HostName <server-host> `
  -Port <ssh-port> `
  -User root `
  -KitRoot D:\hxjh\trace-g-server-kit-g5 `
  -RemotePersistRoot /data/trace-g-g5
```

## 服务器 CPU staging

上传完成后，以 root 执行：

```bash
cd /data/trace-g-g5/trace-g-server-kit
TRACE_G_PERSIST_ROOT=/data/trace-g-g5/runtime \
  bash scripts/server_stage_g5.sh "$PWD"
```

staging 会依次验证 `SHA256SUMS`、G5 锁内四项工件摘要，加载两个镜像，原子安装源码，核对加载后的
Image ID/标签，并在锁定 Controller 容器中运行 G5 聚焦单测。任何既有目录与 source marker 不匹配时
都会停止，不覆盖未知服务器数据。

## GPU 阶段门

选择服务器物理 GPU 编号，使用新的 run ID：

```bash
cd /data/trace-g-g5/runtime/wp2-redteam
TRACE_G_PERSIST_ROOT=/data/trace-g-g5/runtime \
  bash scripts/server_run_g5_gate.sh g5-server-001 0
```

正式通过必须同时满足：

- 父 recording 和 carrier fork 的 live Episode 使用锁定真实 Qwen；
- 父/子 strict replay 精确匹配，但不启动 Ollama、不调用 Qwen 且不申请 GPU；
- 四个 Episode 都是 `--network none`、只读根文件系统、无 bind mount、无 Docker Socket；
- live 容器内存在 `/usr/bin/ollama serve`，模型、Agent、13 项工具和办公状态属于同一容器；
- 父 Manifest 和可达 Artifact 不变，子分支独立；
- 源/重放行为 profile 与风险签名一致；
- 结束后 Agent 容器和 workspace volume 残留均为 0。

通过后生成：

```text
reports/trace-g-g5-server-001-g5-results.tar.gz
reports/trace-g-g5-server-001-g5-results.tar.gz.sha256
```

失败时生成带 `-g5-failed` 的归档。失败归档必须保留，但绝不能作为通过证据。

## 回收后离线复核

先验证下载归档的 `.sha256`，解压后运行：

```powershell
& 'C:\Users\17816\anaconda3\envs\trace-redteam311\python.exe' `
  scripts\validate_g5_server_results.py `
  --result-root <解压后的 run 目录> `
  --lock <run 目录>\g5-server-kit-lock.json
```

只有服务器归档、离线复核和零残留同时通过，路线图才能把 5.G5 标为完成并进入 5.G6。
