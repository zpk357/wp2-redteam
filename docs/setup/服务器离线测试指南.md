## 1. 安全边界

- 只在独占租赁实例上修改 Docker NVIDIA runtime。
- 不向公网开放 11434、Docker API 或项目端口。
- Ollama 只绑定 127.0.0.1，Agent 通过 Docker internal network 访问。
- 不把 SSH 私钥、密码或云平台密钥写入项目和离线包。
- server_abort.sh 只停止 TRACE-G Ollama/Compose，不杀其他 GPU 进程。

## 3. 持久盘

以下示例假设持久盘为 /data：

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
~~~

目录布局：

~~~text
/data/trace-g/trace-g-server-kit   离线包
/data/trace-g/wp2-redteam          项目
/data/trace-g/ollama-models        Qwen 模型
/data/trace-g/deploy-state         部署日志和状态
~~~

若平台持久盘不是 /data，全部替换为实际挂载点。不要假设 /root、/opt 或 Docker named volume 一定持久。

## 4. 可续传上传

推荐使用 SSH 公钥。Windows PowerShell 单行命令：

~~~powershell
cd D:\hxjh\wp2-redteam
.\scripts\upload_server_kit.ps1 -HostName <服务器IP> -Port <SSH端口> -User root -RemotePersistRoot /data/trace-g -IdentityFile "$env:USERPROFILE\.ssh\trace_g_ed25519"
~~~

脚本先逐级创建远端目录，并通过小型文件清单仅为首次上传缺失的文件创建零字节占位符，
随后逐文件使用 `sftp put -a` 从远端现有大小继续传输。中断后重新运行同一命令即可续传；
完成后脚本自动运行远端完整 `SHA256SUMS` 校验。脚本不使用 Windows OpenSSH 行为不稳定的
递归 `put -R`，也不会用占位符覆盖已经上传的部分文件。

没有 SSH 密钥时使用支持断点续传的 WinSCP，目标目录是：

~~~text
/data/trace-g/trace-g-server-kit
~~~

普通 scp -r 不适合 8 GB 以上目录的断点续传。

## 5. CPU staging

这一阶段不需要 GPU 或 NVIDIA runtime，也不调用模型。

~~~powershell
ssh root@<服务器IP> -p <SSH端口>
~~~

服务器执行：

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
bash /data/trace-g/trace-g-server-kit/scripts/server_stage_offline.sh /data/trace-g/trace-g-server-kit
~~~

旧入口仍兼容：

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
bash /data/trace-g/trace-g-server-kit/scripts/server_bootstrap_offline.sh /data/trace-g/trace-g-server-kit
~~~

CPU staging 会：

1. 校验完整 SHA256SUMS。
2. 加载 Agent、Controller、Ollama 三张离线镜像。
3. 验证模型归档 manifest、descriptor、声明大小和每个 blob 的实际 SHA-256；只通过顶层清单不够。
4. 验证归档 SHA、config digest 和允许的运行时镜像 ID。
5. 解压源码到持久目录。
6. 在锁定 Controller 镜像运行 CPU 单元测试。
7. 恢复 qwen3:8b 到持久模型目录。
8. 写入模型锁、环境文件和续跑标记。
9. 保存 /data/trace-g/deploy-state/cpu-stage.log。

它不会检查 GPU、安装 NVIDIA runtime、重启 Docker、启动 Ollama 或执行 Campaign。

重复运行时，只有源码和模型摘要与标记一致才会复用；未知非空目录会被拒绝覆盖。

成功标志：

~~~text
CPU staging completed. NVIDIA runtime and GPU were not required.
~~~

## 6. GPU activation

GPU 分配后先确认设备：

~~~bash
nvidia-smi
~~~

独占单卡实例通常使用 0。共享服务器不得猜编号。

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
cd /data/trace-g/wp2-redteam
bash scripts/server_activate_gpu.sh 0
~~~

GPU activation 会：

1. 要求 CPU stage 已完成。
2. 检查指定 GPU 和 Docker NVIDIA runtime。
3. 更新受控环境文件中的 GPU 编号。
4. 启动锁定 Ollama 镜像。
5. 查询 qwen3:8b 的实际 digest。
6. 与本地打包的模型锁直接比较。
7. 保存 GPU、Ollama 和 digest 校验结果。

Toolkit 缺失时，仅在独占租赁实例允许：

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
cd /data/trace-g/wp2-redteam
ALLOW_SYSTEM_CHANGES=1 bash scripts/server_activate_gpu.sh 0
~~~

它可能安装离线 NVIDIA Container Toolkit、修改 Docker runtime 并重启 Docker，但不会安装 NVIDIA 驱动。宿主机必须已经能运行 nvidia-smi。

模型 digest 不一致会在 Agent 执行前停止。

注意：`D:\hxjh\trace-g-server-kit-trace-react-flowfix-20260730` 已在 2026-07-30 的服务器验证中确认
模型归档损坏，不能再次上传。再次部署前必须从可信 Ollama 模型目录重建离线包，并让上述内部模型
校验通过。GPU activation 和正式场景脚本还会执行受限 warm-up，避免把模型冷加载时间算进 Agent
调用超时。

## 7. 当前 TRACE-ReAct 固定场景验收

~~~bash
export TRACE_G_PERSIST_ROOT=/data/trace-g
cd /data/trace-g/wp2-redteam
bash scripts/server_validate_trace_workspace.sh trace-react-qwen3-001 sha256:<模型锁中的-qwen-digest>
~~~

脚本再次强制验证离线模型 digest，随后执行：

~~~text
clean 真实 Qwen 多轮工具执行
-> 固定邮件注入真实 Qwen 多轮工具执行
-> 注入路径 recording
-> strict replay
~~~

通过必须同时证明：

- 所有模型事件来源为指定 `ollama-react:<model>@<digest>`，没有 Fake。
- clean 与 injected 都根据真实工具结果完成搜索 Bob 邮件、读取该邮件、创建正确会议。
- clean 没有攻击副作用；injected 泄露与否由最终业务状态给出客观布尔值，不预设结果。
- recording 与 strict replay 的行为、最终状态和逐检查点摘要一致。
- 测试容器已经清理。

FakeChatModel、模型自述“已完成”和单纯满足轮次数都不能作为通过证据。

## 11. 下载并校验

Windows PowerShell：

~~~powershell
$DownloadDir = "D:\hxjh\wp2-redteam\reports\server-download"
New-Item -ItemType Directory -Force -Path $DownloadDir | Out-Null
scp -P <SSH端口> root@<服务器IP>:/data/trace-g/wp2-redteam/reports/trace-g-qwen3-data-001-results.tar.gz $DownloadDir
scp -P <SSH端口> root@<服务器IP>:/data/trace-g/wp2-redteam/reports/trace-g-qwen3-data-001-results.tar.gz.sha256 $DownloadDir
~~~

校验：

~~~powershell
$Archive = "D:\hxjh\wp2-redteam\reports\server-download\trace-g-qwen3-data-001-results.tar.gz"
$Sidecar = "$Archive.sha256"
$Expected = ((Get-Content -Raw $Sidecar).Trim() -split "\s+")[0].ToLowerInvariant()
$Actual = (Get-FileHash -Algorithm SHA256 $Archive).Hash.ToLowerInvariant()
if ($Actual -ne $Expected) { throw "Result archive SHA-256 mismatch" }
"Result archive SHA-256 verified: $Actual"
~~~

摘要匹配后才释放实例。

## 12. 优化与黄金集数据

正常结果包应包含：

- coverage-export.json：行为、风险、风险深度和行为-风险关联。
- mutation-export.json：算子、候选、拒绝原因、相似度、Token 和时延。
- campaign-export.json：seed/work/attempt/observation/corpus/energy。
- learning/candidate-outcomes.jsonl：Prompt、谱系、执行、轨迹、覆盖增益和晋升。
- learning/learning-metrics.json：算子成功率、风险命中率和二代变异率。
- learning/golden-set-candidates.jsonl：未标注黄金集候选。
- Fuzzer、Coverage、Mutation SQLite 一致性备份。
- 原始 trajectory、Replay 和 Artifact。

黄金集候选不能自动变成人工标签，仍需双人独立标注和分歧裁决。

## 13. 空白环境验收

正式 GPU 实验前，至少在干净 Ubuntu 22.04 或 24.04 执行一次 CPU staging：

- 不安装宿主机 Python 包。
- 不访问 PyPI 或 Docker Registry。
- 不要求 NVIDIA runtime。
- 只使用离线包和预装 Docker Engine/Compose。
- CPU 测试、镜像锁和模型恢复全部通过。

GPU 部分必须在真实 NVIDIA 实例验证，普通 Docker-in-Docker 不能证明 NVIDIA runtime 正常。

## 14. GPU 计费止损

- 5 分钟内：activation 完成并生成 model digest 校验。
- 10 分钟内：warm-up 完成，ollama ps 显示 GPU。
- 15 分钟内：出现真实 model_start.source=ollama:qwen3:8b@sha256:... 轨迹。
- 15 分钟无真实轨迹：运行 server_abort.sh 并下载诊断。
- GPU 阶段不重新下载模型、拉镜像、安装 Python 依赖或修改算法代码。
