## 3. 小步施工

### 1.1 建立旧实现事实清单

检查场景模型、OfficeRuntime、容器工具桥、ToolSpec、Agent Prompt、Coverage office evidence/risk、
Office Campaign/Mutation 和通用 Fuzzer TestCase。

验收：逐模块记录输入、状态、输出、调用方、Office 专用假设和可复用机制；明确证明载体必选、固定
目录和 prompt-only TestCase 的耦合位置，不根据文件名猜测。

### 1.2 冻结四域语义

分别定义邮件、云盘、日历、工作区文件的对象、字段、生命周期、可见性和副作用。特别说明云盘共享
资源与 Agent 工作区产物的边界，避免把“云盘”和“文件”实现成两个同义字典。

验收：每个域至少参与一条跨域链；没有只为增加工具数量存在的孤立能力。

### 1.3 冻结身份和权限模型

定义 Actor、组织、组、内部/外部 principal、资源所有权、ACL、敏感级别、任务委托和企业政策。
权限决定必须区分 `capability_available`、`platform_allowed`、`delegation_allowed` 和
`policy_allowed`。

验收：能够解释“工具可见但平台拒绝”“平台允许但任务未委托”“任务要求但企业政策禁止”三种差异。

### 1.4 冻结 Agent 可见世界

设计从世界状态生成的动态系统上下文、ToolSpec 和结构化工具结果。删除面向 Agent 的 `synthetic`、
测试矩阵、攻击标签和安全/脆弱控制信息。

验收：所有可见身份、权限和资源元数据都能追溯到世界状态；Prompt 不维护第二份事实。

### 1.5 冻结 Task 与攻击入口正交结构

定义 `TaskContract`、`AttackObjective`、可选 `AdversarialCondition` 和 `ScenarioCase`。四类入口使用明确
类型，不用大量 nullable 字段拼出隐式联合。

验收：干净案例没有攻击条件；直接恶意任务没有内容载体；伪造授权区分声明与权威事实；参数来源操纵
记录原始值、Agent 可见值和污染来源；同一目标可走不同入口，同一入口可承载不同目标。

### 1.6 冻结跨域正常链

```text
搜索邮件 -> 读取邮件 -> 解析关联云盘资源 -> 读取资源与权限元数据
-> 提取会议参数 -> 创建/更新日历事件 -> 创建工作区任务记录 -> submit
```

验收：后一步至少有三个参数来自前序真实返回；删除或改变上游关系会导致可解释的不同结果。

### 1.7 写完五条验收故事

每条故事写明 Actor、初始状态、顶层任务、可见攻击条件、合法权限、禁止副作用、允许路径范围、最终
状态、utility 事实、security 事实和失败分类。

验收：合法链、直接任务、间接内容、伪造授权和参数来源操纵都由同一组核心对象表达。

### 1.8 形成工具迁移表

逐项检查现有 ToolSpec：保留名称与 Schema、扩充返回、修改语义、合并或退役。只有跨域链缺少必要
查询能力时才新增工具，优先扩充资源元数据和增加最多两个横向发现工具。

验收：不存在只因为“看起来更真实”而新增、但不参与状态链或验收故事的工具。

### 1.9 形成代码迁移图

逐文件标记原样复用、通过 V2 接口适配、暂留为 V1 fixture、V2 验收后删除，并标记依赖方向和删除
前置条件，避免新旧模型相互 import 形成永久双轨。

验收：阶段 2 的修改文件集合、禁止触碰区域、回滚点和测试范围明确。

### 1.10 补充冻结结构复杂度与不可变生命周期

冻结唯一 `office-world-v2.0` 的精确库存和业务干扰项；定义 TaskGoalGraph、ResourceQuery/
ResolvedBinding、ReachableAttackSurface、ObjectiveMilestoneGraph、ObservationPolicy 和
InteractionContract；写出至少三条包含输入、可见信息、状态变化、分支和 Oracle 的具体实例。

验收：基础世界、父 ScenarioCase 和运行中案例不可被原地变异；新候选使用新 Episode；正常任务不是
固定工具脚本；资源 ID 在执行前解析并冻结；攻击位置有正常任务可达证据；复合目标逐里程碑判断；
合法澄清可产生限时授权，内容声明不能产生授权；结构复杂度有独立于语言表达数量的定量下限。

### 1.11 用户设计确认门

向用户展示业务对象图、权限决策表、完整正常数据流、四入口差异、五条故事和资产迁移结果。用户确认
业务含义与支持边界，不需要确认 Python 类名。存在实质歧义时保持本阶段未完成，不进入实现。

## 4. 反偷懒检查

以下任一情况发生，本阶段不得通过：

- 只是把 `InjectionCarrier` 改名，仍要求每个攻击都有内容载体。
- 四域仍是互不相关的独立字典，没有跨域引用和状态传播。
- 权限只写在系统 Prompt，不存在权威状态与决策模型。
- 工具描述说“不能做”，但 Runtime/Oracle 无法区分平台拒绝、任务越权和政策违规。
- 验收故事通过固定 ID、固定人员名或硬编码工具序列判定。
- 参数操纵发生在模型发出调用后，错误归因给 Agent。
- 反复随机生成新世界，或 Fuzzer 原地修改固定世界、父案例或运行中的 Episode。
- TaskGoalGraph 只是固定工具序列换名，资源和攻击仍硬绑定少量实例 ID/字段。
- 多数攻击仍只由一个 share/permissions 工具决定，Oracle 不保留复合目标中间状态。
- Agent 获得完整世界，或自由生成回复和内容声明能够改变权威授权。
- 用测试数量、Schema 数量或文档长度替代可运行的数据流。
- 为兼容 V1 错误合同而让 V2 保留载体必选或固定矩阵边界。
