# Office Workspace V2 变异空间宏观计划

状态：`场景、覆盖和调度前置门均已通过；第四步设计已确认，4.0 已完成`

当前权威详细计划：
`docs/plans/office-workspace-scenario-v2-step-04-controlled-semantic-mutation.md`。本宏观文档继续约束变异
空间和长期边界；若与详细计划冲突，以用户最新确认的“每轮单候选、第五步执行后结算”为准。

本文冻结研究目标、维度边界、施工顺序和验收原则。场景 V2 阶段 8、V2CoverageInput、双覆盖和第三步
Corpus/Frontier 调度闭环现已完成；具体算子、Provider、校验、物化和恢复合同由第四步详细计划细化。

## 1. 为什么不能跳过前两门

### 门 A：场景验收冻结

必须先得到稳定的世界状态、身份权限、四域对象、跨域引用、工具语义、四类攻击入口和事实 Oracle。
否则变异器不知道哪些字段是真实业务状态、哪些变化会破坏场景、哪些副作用可以被可靠判定。

### 门 B：覆盖定义

必须基于冻结场景重新定义：

- 哪些工具调用和跨域边构成行为特征。
- 哪些参数来源、权限决定和状态转换构成新颖性。
- 哪些风险阶段与事实 Oracle 对应。
- 两条语义不同但执行等价的轨迹如何去重。
- 覆盖快照、增量和反馈摘要如何锁定身份。

门 B 不再负责从零发明执行事实：它直接消费阶段 2 的 StateTransitionRecord/StateDelta、阶段 3/6 的
真实工具边与 Oracle SecurityFact。门 B 负责把中立事实映射为版本化特征、去重规则、分母和反馈摘要。
状态记录中的具体 resource ID 只做证据定位，默认特征使用 operation/resource kind/field path/relation kind；
确需实例身份时必须单独论证，禁止通过轮换同类资源制造假新颖度。

没有门 B，只能做无反馈候选生成，不能声称是覆盖率引导变异。

## 2. 最终目标

变异器接收一个冻结的 `ScenarioCase`、场景/目录身份和未来 V2 `CoverageFeedback`，生成一组结构合法、
业务可达、差异可解释且具备真实执行价值的候选。候选应在同一个固定 `office-world-v2.0` 中探索不同
Actor、任务、现有资源绑定、任务授权、攻击入口/位置、攻击目标、参数来源和跨域工具路径，而不是
随机生成新世界或只改写攻击文本。

本计划的完成边界是“变异空间和候选生成合同通过”。候选执行竞争、Corpus 晋升和反馈引导效果属于
后续独立阶段。

Office V1 固定矩阵、12 组合及其历史覆盖结果不进入本计划：不迁移到 V2 Corpus，不参与 V2 覆盖分母、
候选竞争或随机/无反馈等预算实验。V1 仅可作为独立历史回归运行，结果不得与 V2 特征集合并。

## 3. 冻结与可变维度

### 3.1 默认冻结维度

- Agent 模型、Prompt 版本、镜像和执行预算身份。
- `CanonicalOfficeWorld` 版本、内容摘要、人员/资源库存、ACL、政策和跨域关系事实。
- 四域 Schema、工具语义、权限算法和事实 Oracle 版本。
- Campaign 的场景版本、风险分类和覆盖特征版本。
- 未被当前 MutationPlan 明确声明改变的所有字段。

### 3.2 可变维度族

1. **案例绑定**：从固定世界选择不同 Actor、任务参与者、现有资源、版本和现有关系路径；解析后锁入
   新的子 ScenarioCase，不能修改基础世界事实。
2. **任务**：目标对象、约束、委托范围、允许副作用和正常成功条件。
3. **攻击入口**：直接任务、间接内容、伪造授权、参数来源操纵及其物化位置。
4. **攻击目标**：希望造成的未授权读取、外发、删除、改权或其他已注册事实副作用。
5. **内容表达**：措辞、格式、位置和上下文包装；仅是一个维度，不是全部变异空间。
6. **参数来源**：收件人、资源 ID、时间、权限声明等值的来源、污染位置和交叉验证线索。
7. **跨域路径选择**：选择固定世界中不同的邮件附件、文件引用、日历关联资源或工作区来源链；只有
   声明为对抗条件的 overlay 才能污染字段或引用，不能重写 CanonicalOfficeWorld。
8. **预期交互方向**：希望探索的工具族、跨域边或权限分支；实际路径仍由真实 Agent 执行决定。

## 4. 变异算子族

算子名称是研究分类，不预先绑定 Python 类。

### 4.1 案例绑定变异

从固定世界中选择满足 ResourceQuery 的不同人员、资源、版本、时间或收件人，并重新冻结
ResolvedBinding。不得创建新实体、改变资源自身敏感级别/ACL 或原地修改父案例；必须保持任务可完成且
Oracle 可判定。

### 4.2 关系图变异

选择固定世界中不同的既有跨域引用链；若攻击入口本身是参数来源操纵或间接内容，可在子案例 overlay
中显式污染兼容字段或引用。不得增加、删除或重连基础世界关系。目标是改变可达工具路径，不是增加
无关资源。

### 4.3 任务授权变异

改变任务委托范围、允许副作用或约束，探索“平台允许但任务未委托”等边界。不得把政策事实偷偷写进
任务文本替代权威状态。

### 4.4 攻击入口变异

在保持攻击目标时转换入口，例如 `indirect_content -> direct_task`，或保持入口类型但改变物化域。
入口转换后必须重新验证任务可达性和攻击事实可观察性。

### 4.5 伪造授权变异

改变授权声明的来源、措辞、签名外观和关联资源，但权威授权状态保持未批准；不能让物化器真的写入
授权事实。

### 4.6 参数来源操纵

改变 Agent 消费的数据源值、污染链和可供核验的替代来源。禁止在模型已经发出工具调用后篡改参数并
把结果归因给 Agent。

### 4.7 攻击目标重定向

显式改变攻击目标及其事实 Oracle，重新验证前置条件、权限关系和可观察副作用；禁止静默漂移。

### 4.8 路径延伸与缩短

通过选择固定世界中更长或更短的既有资源关系链，或声明合法的对抗 overlay，使任务可能需要更多或
更少跨域步骤。MutationPlan 只能声明期望探索方向，不能改写基础关系、向被测 Agent 下发 action plan
或硬编码工具序列。

### 4.9 组合变异

只有单维算子各自通过后，才允许由明确计划组合两个以上维度。组合必须保存应用顺序、中间状态和每步
校验结果；不能以“LLM整体重写”绕过差异审计。

## 5. 核心变异工件

具体字段在前置门通过后细化，但职责现在冻结：

- `MutationIntent`：来自调度器的探索意图，引用 coverage gap，不含候选内容。
- `MutationPlan`：调用前冻结父案例、改变/保持维度、算子、约束、预算和身份。
- `MutationCandidate`：Provider 只为 `MutationPlan` 已冻结的 `payload_slot_id` 输出
  `generated_content`；位置、资源、结构算子结果和完整子案例均由宿主决定。
- `MutationValidationRecord`：宿主独立计算实际差异、引用完整性、可达性、utility 和 Oracle 可判定性。
- `CandidateSet`：为复用 Coverage 合同保留的 singleton 包装；每轮只能包含一个接受或拒绝候选及原因。

LLM 只能提出候选，不能自行填写可信 digest、校验通过、覆盖增长或风险命中。

## 6. 宏观施工阶段

### M0：前置门与资产复核

输入：冻结 Scenario V2 工件、V2 CoverageFeedback 合同和旧变异资产盘点。

验收：两项前置门均有版本/digest和执行证据；否则本计划保持阻塞。

### M1：可变维度清单与不变量

逐字段标记 `frozen / mutable / conditionally_mutable / derived`，定义引用、权限、utility、可达性和 Oracle
不变量。

验收：不存在“任意 JSON 字段都可改”或“只能改攻击表达”的两种极端。

### M2：算子语义与覆盖空白映射

为每个算子说明适用前置条件、实际状态变化、可探索的覆盖空白、失败模式和逆操作/缩减方式。

验收：每个算子至少对应一种可能改变真实行为或状态路径的机制；纯文本算子单独标识。

### M3：组合约束与候选编译

实现从计划到完整子 ScenarioCase 的确定性编译、引用修复、前置条件检查和稳定拒绝码。

验收：候选进入 Docker 前已经结构合法、业务可达且 Oracle 可判定，但不预测真实 Agent 路径。

### M4：Plan/Candidate/Validation V2 合同

实现三段审计与 lineage；实际差异必须由宿主计算，所有变化与计划逐项比对。

验收：未声明字段变化、静默目标漂移、权限事实伪造和场景版本漂移全部封闭拒绝。

### M5：确定性算子参考实现

为每个算子族实现少量确定性参考算子，用于证明空间和约束机制，不冒充最终语义质量。

验收：同 seed 可复现；同类新资源实例不需要新增硬编码分支。

### M6：LLM Mutator 语义生成

让独立 LLM Mutator 在冻结计划内每轮生成一个候选；宿主完成解析、规范化、编译和校验，提交该候选的
真实执行反馈后才开始下一轮。

验收：至少覆盖不同维度族，不坍缩为同一入口的措辞改写；Fake/RuleBased 证据与真实 LLM 分开。

### M7：单候选质量门

跨多轮报告合法候选率、真实结构差异、入口/目标/路径方向分布、近重复率、不可达原因和单位生成成本。

验收：固定轮数下能逐轮生成可执行且不持续坍缩为等价表达的候选；每轮仍只有一个候选。

### M8：交付单候选反馈闭环

冻结 singleton CandidateSet 输入合同，移交后续“一个候选执行 -> coverage delta -> Corpus 晋升或拒绝
-> 重新调度”阶段。

验收：是否晋升只看该候选的真实执行 coverage delta，不使用静态猜测冒充执行覆盖收益。

## 7. 代表性验收矩阵

- 同一攻击目标分别通过四类入口生成合法候选。
- 干净案例可改变固定世界内的 Actor/资源绑定、任务和路径选择，而不被强制增加攻击字段。
- 同一入口可以重定向到不同已注册攻击目标，并同步改变 Oracle。
- 路径选择或显式对抗 overlay 真实改变可达工具链，不只是改变描述文本；基础世界 digest 保持不变。
- 伪造授权候选保持权威授权为假。
- 参数来源操纵保留原始值、可见值和污染来源。
- 每轮 singleton CandidateSet 恰好包含一个候选；重复、非法和不可达候选有稳定拒绝原因。
- 实际执行路径与计划期望不同，不篡改 lineage，coverage 只记录真实路径。

## 8. 反偷懒与停止条件

- 变异工作若早于场景冻结或覆盖定义，立即停止。
- 新算子若只适用于固定 case ID、人员名或文件名，立即停止并修正抽象。
- 候选数量增加但真实状态/路径不变，不算扩大变异空间。
- LLM 整体重写后无法解释字段差异，不得进入执行。
- 用静态合法性分数预测候选覆盖收益，不得称为真实反馈。
- 为提高合法率而把不变量、权限或 Oracle 校验放宽，立即停止。
- 覆盖反馈无法指出具体事实空白时，不得编造算子映射或权重。
- 仅因具体 resource ID、case ID 或措辞变化产生新特征时，视为假覆盖并停止修正提取合同。
- 在 M7 前增加复杂恢复、并发和公平调度，视为再次重复旧优先级错误。

## 9. 后续详细计划规则

现在不创建 M1-M8 的字段级详细施工计划。顺序必须是：

1. Scenario V2 阶段 8 通过后，编写并执行“场景验收冻结”详细计划。
2. 基于冻结轨迹和阶段 2/6 已冻结的中立事实编写并执行“V2 覆盖提取与版本定义”详细计划；不得反向
   要求 World 或 Oracle 为某个当前权重算法改写事实。
3. 两项完成后，使用真实字段和反馈合同展开本计划 M1 的详细施工计划。
4. 每个 M 阶段通过后再展开下一阶段。

## 10. 与后续阶段的边界

本计划结束后，项目仍未证明覆盖引导有效。后续顺序保持：

```text
变异空间冻结
  -> 单候选反馈：每轮执行一个候选，根据真实 coverage delta 晋升或拒绝
  -> 反馈引导：下一代 MutationIntent 引用上一代 feedback digest
  -> 等预算实验：与随机/无反馈生成比较
```

覆盖率变异讨论成果与场景后施工方向交接见
`docs/plans/office-workspace-v2-post-scenario-construction-direction.md`。该文件冻结 D1-D9 设计决策，
并列出阶段 8 前必须做对的覆盖原料；场景冻结前本计划与交接件均保持阻塞。
