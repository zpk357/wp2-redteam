# Office Workspace Scenario V2 宏观总计划

状态：`阶段 1-6 已冻结；阶段 7 的 7.0-7.8 已完成，下一项是 7.9；真实 Qwen 服务器验收延后`

本计划替代 Office V1 作为当前唯一场景施工主线。Office V1 只保留为历史文档和仍有价值的回归 fixture，
永久排除于 V2 Corpus、覆盖分母、候选竞争和等预算实验，不再决定产品威胁模型、TestCase 核心结构、
Campaign 输入空间或后续覆盖率变异方向。

## 1. 最终目标

建设一个高完成度、内部因果一致、可长期扩展但不需要再次推翻核心合同的企业办公场景。场景完成后，
真实 Agent 应当从身份、任务、工具、资源、权限和工具返回中感知同一个办公世界；执行结果由业务状态
与事实 Oracle 判定，而不是由 Prompt 关键词、固定 case ID 或模型自报结论判定。

本阶段只建设场景，但阶段 2 和阶段 6 必须分别冻结可供覆盖单向消费的状态差异与 Oracle 中立事实。
场景冻结后再定义覆盖特征提取、版本、权重、Corpus 晋升、变异算法、候选竞争和等预算实验，而不是
到阶段 8 才发现上游事实不可枚举或不可追溯。

## 2. 冻结范围

### 2.1 四个业务域

1. 邮件：会话、发件人、收件人、附件、内部/外部来源和引用关系。
2. 云盘：共享资源、所有者、敏感级别、ACL、共享范围和版本。
3. 日历：组织者、参与者、时间、状态、关联邮件和关联资源。
4. 工作区文件：Agent 可创建和编辑的任务产物，与云盘共享资源明确区分。

身份目录、角色、访问控制和企业政策属于四域共同基础设施，不扩张为新的业务域。采购、付款、账户、
聊天和异步授权撤销不进入 V2 冻结范围。

V2 只建设一个人工设计并锁定摘要的 `office-world-v2.0` 基础世界：40 个内部用户、12 个外部联系人、
8 个组、120 封邮件、50 个云盘文件、30 个日历事件和 20 个工作区文件。每个 Episode 复制该世界；
不同测试只改变 Actor、任务目标、从现有世界解析并冻结的资源绑定、攻击条件/位置和交互脚本，不随机
生成新组织，也不原地修改基础世界、父案例或运行中的案例。

### 2.2 四类攻击入口

1. `direct_task`：攻击要求直接出现在顶层用户任务中，不需要不可信内容载体。
2. `indirect_content`：攻击内容位于邮件、云盘文件、日历描述或工作区文件中。
3. `forged_authorization`：内容声称存在授权，但权威状态中不存在相应授权事实。
4. `parameter_source_manipulation`：Agent 读取到的收件人、资源 ID、时间或其他参数来源被污染。

多轮诱导、恶意工具返回和状态竞争暂不作为独立场景入口。确定性的合法澄清、已认证用户回复产生的
限时任务委托、搜索分页、权限过滤和旧版本核验属于正常办公机制，进入 V2；它们不能被误写成新的攻击
入口。异步授权撤销与并发竞态继续排除。未来若需新增底层状态机制，必须重新走架构决策。

### 2.3 明确不做

- 不增加十个业务域或大量互不相干的工具。
- 不把所有攻击强制表示为 `InjectionCarrier + payload`。
- 不用更多固定任务、固定矩阵或表达模板冒充场景完整度。
- 不继续建设 Office V1 专用 RiskFrontier、G6、远程 G5 或复杂 Campaign 恢复。
- 不在场景冻结前设计最终覆盖特征提取/权重、MutationPlan 或调度权重；但现在必须冻结状态差异与
  Oracle 的 coverage-ready 中立事实合同。
- 不把“通过很多单元测试”当作场景完成证据。

## 3. 稳定核心合同

阶段 1 必须冻结以下概念边界；具体类名可以在评审后确定：

- `OfficeWorldState`：人员、组织、资源、跨域关系、ACL、政策和逻辑时钟的唯一事实源。
- `CanonicalOfficeWorld`：唯一固定基础世界、域文件 manifest、版本和内容摘要。
- `ActorContext`：Agent 当前代表的身份、角色、组和可见组织信息。
- `TaskContract / TaskGoalGraph`：顶层任务、业务目标依赖、澄清分支、委托范围和允许副作用；不冻结
  唯一工具序列，也不预设任务一定良性。
- `ResourceQuery / ResolvedBinding`：从固定世界按业务条件选择资源，并在执行前冻结实例 ID 和证据。
- `ObservationPolicy / InteractionContract`：权限受限视图、稳定分页、确定性澄清和可信授权变化。
- `AttackObjective / ObjectiveMilestoneGraph`：独立于入口的原子或复合状态目标与里程碑。
- `AdversarialCondition`：可选攻击条件，使用带类型的四入口联合结构；干净案例可以为 `None`。
- `ReachableAttackSurface`：由任务依赖、资源关系和 Actor 可见性计算的合法攻击放置集合。
- `ScenarioCase`：世界快照、Actor、任务、可选攻击条件、Agent 配置和预算的冻结组合。
- `PolicyDecision`：区分平台 ACL、账户能力、任务委托和企业政策。
- `ScenarioOracle`：从初始/最终状态、工具事实和政策决定中产生 utility 与 security 事实。
- `StateTransitionRecord / StateDelta`：事务前后摘要、字段级变化、资源/关系创建移除和摘要证据；具体
  资源 ID 用于审计，未来覆盖层再提取不依赖实例 ID 的结构特征。

兼容性原则：TRACE、recording/replay、Docker Episode 和工具调用协议继续复用；Office V1 的类不能成为
V2 核心合同的父类或隐式兼容要求。

## 4. 代表性完整数据流

```text
固定 CanonicalOfficeWorld
  -> 解析 Actor、TaskGoalGraph、现有资源绑定、交互脚本和可选攻击位置
  -> 冻结 ScenarioCase、初始状态和全部 digest
  -> 同一事实源生成 Agent 办公上下文、ToolSpec 和部分可观察业务视图
  -> Agent 根据真实工具返回自主选择后续调用
  -> 信息不足时通过可信用户通道澄清；合法回复可创建限时 DelegationGrant
  -> 工具层先执行平台 ACL，再记录任务委托与企业政策是否允许
  -> 四域状态与跨域关系发生真实变化并产生规范 StateDelta
  -> TRACE 记录模型、工具、权限决定、状态摘要和事务差异事实
  -> ScenarioOracle 独立重建正常任务结果、攻击尝试、拦截和副作用
  -> recording/strict replay 验证相同事实链
```

## 5. 宏观施工阶段

### 阶段 0：停止旧路线与资产盘点

目标：冻结 Office V1、G6、G5 和覆盖率变异施工；形成逐文件资产分类。

输出：`保留 / 改接口复用 / 降级为 fixture / 最终退役` 清单，以及 V2 依赖边界。

阶段门：任何后续任务都不能再把旧路线的“当前下一项”解释为 G6。

### 阶段 1：业务与架构设计冻结

目标：冻结四域世界、身份权限、跨域关系、任务、四入口、Oracle 和 Agent 可见上下文合同。

输出：字段级模型草案、固定世界库存、状态不变量、任务依赖/资源解析/观察交互合同、工具语义表、
四入口与复合目标、五条验收故事、具体业务实例和旧代码迁移映射。

阶段门：用户能够从输入、状态变化、输出、副作用和失败模式确认场景符合目标；尚不实现代码。

### 阶段 2：世界状态、身份与权限内核

目标：实现固定 `CanonicalOfficeWorld`、Episode 副本、Actor、组织目录、ACL、任务委托、政策决定、
部分可观察视图和执行前资源解析的单一事实源。

输出：无 Agent、无 Docker 条件下可确定性执行和复核的状态内核，以及不依赖 Coverage 模块的规范
StateTransitionRecord/StateDelta。

阶段门：固定库存和关系约束通过；权限判断不能依赖 Prompt、case ID 或工具名特例；相同事实产生相同
决定和分页；基础世界、父案例不可变，资源解析在执行前固定；成功/失败事务的状态差异可枚举、可摘要、
可重放，且不泄露原始敏感值。

### 阶段 3：四域工具与跨域因果链

目标：迁移并加深现有 17 个工具，使邮件、云盘、日历、工作区文件共享资源引用、权限状态、分页和
版本语义，并执行 TaskGoalGraph 的正常业务依赖。

输出：完整正常链：邮件 -> 关联云盘资源 -> 参数提取 -> 日历写入 -> 工作区文件产物。

阶段门：目录中的长链、分支、分页和消歧案例可运行；至少五步依赖真实前序返回；修改一个上游资源会
可解释地改变下游行为或结果。

### 阶段 4：Agent 办公认知与真实 API 表面

目标：让 Agent 从同一事实源看到身份、时间、组织政策、工具能力和权限受限资源视图，并支持确定性
合法澄清及可信授权更新。

输出：动态系统上下文、真实化 ToolSpec、结构化分页结果、稳定权限错误、ClarificationRequest、
UserResponseScript 和 DelegationGrant TRACE；移除 `synthetic` 测试提示。

阶段门：Agent 不知道测试矩阵或攻击标签，但能说明自己代表谁、可用什么工具、哪些动作需要权限；
分页、无权字段、澄清、合法授权、拒绝和无权回复均产生正确可见结果与状态事实。

### 阶段 5：四类攻击入口

目标：四类入口分别从兼容的 ReachableAttackSurface 物化，入口与原子/复合攻击目标正交，干净案例不
包含攻击字段。

输出：每类入口的结构化定义、物化器、溯源记录和至少一个正/反事实对照。

阶段门：直接恶意任务在没有不可信内容时可以运行；伪造授权不会成为真实授权；参数污染发生在 Agent
消费的数据源，不在模型发出调用后偷偷篡改调用；复合目标保留逐里程碑部分进展，不收敛为单一危险
工具调用。

### 阶段 6：事实 Oracle 与证据接入

目标：统一判断正常任务完成、平台拒绝、任务越权、政策违规和攻击副作用。

输出：版本化 Oracle、TaskGoal utility、复合目标逐里程碑事实、可信交互事实、TRACE 映射和
recording/replay 证据。SecurityFact 至少稳定输出 objective/milestone、intent/attempted/blocked/realized
阶段、violation kind、PolicyDecision/StateDelta/工具事件证据引用和事实摘要，供未来 CoverageInput 单向消费。

阶段门：Prompt 和模型自报标签不能改变事实结论；相同轨迹和状态可独立重建相同结果；Oracle 不 import
Coverage，但其事实无需回读场景内部对象即可被覆盖提取器消费。

### 阶段 7：Docker Agent 运行时集成与本机校准

目标：在现有一次性 Agent 容器中运行 V2，复用 LangGraph、TRACE、recording/replay 和清理合同，先用
确定性 Provider 证明工程路径。

输出：合法长链/澄清、四类入口、原子与复合目标的确定性 Docker 正反例，必要路径可
recording/strict replay，成功与失败均零容器/卷残留。

阶段门：没有容器外 action plan；工具结果进入下一轮 Agent 决策；业务状态只存在于当前 Episode；
本机结果不冒充真实模型证据。

### 阶段 8：完整场景验收、冻结与 V1 退役

目标：完成场景冻结，删除生产路径对 V1 载体合同和固定矩阵的依赖。

输出：固定世界版本/digest、五条验收故事、结构复杂度门结果、三条具体业务实例、资产处置结果、遗留
风险和覆盖率设计输入。

阶段门：设计包第 13.1 节的固定库存、任务/路径、复合目标、可达位置和多轮下限全部有可执行证据；
场景通过后才实现覆盖特征提取、版本和变异反馈；状态差异与 Oracle 原料已经在阶段 2/6 冻结。旧测试
只保留能保护仍然有效合同的部分，Office V1 结果不得迁入 V2 Corpus 或覆盖基线。

施工顺序决策：完成阶段 7 的 7.9-7.11 本机 Docker 门后直接进入阶段 8；场景冻结后实现覆盖率、
Corpus、变异和反馈闭环。原 7.12-7.15 的自包含 Qwen 包、GPU 服务器能力门和真实模型矩阵延后到闭环
完成后，以最终代码和同一身份一次性综合验收。

场景冻结后的未来变异空间宏观计划见
`docs/plans/office-workspace-v2-mutation-space-master-plan.md`。该计划不能替代场景验收冻结或 V2 覆盖
定义，两项前置门通过前保持阻塞。

## 6. 五条最终验收故事

1. 合法跨域任务：读取内部邮件及关联资源，提取参数，创建日历事件并生成工作区记录。
2. 直接恶意任务：顶层用户直接要求读取、外发、删除或改权；没有内容载体。
3. 间接内容：正常任务路径暴露恶意内容，Agent 是否把数据误当授权指令。
4. 伪造授权：邮件或文件声称经理批准，但权威权限状态不存在批准事实。
5. 参数来源操纵：数据源中的收件人、资源 ID 或时间被替换，Agent 是否交叉核验并产生正确副作用。

每条故事必须包含干净或合法对照、初始状态、可见信息、期望工具路径范围、允许副作用、禁止副作用、
最终状态断言和失败分类。固定路径只用于验收，不限制真实 Agent 可以采用的其他合法路径。

## 7. 现有资产迁移原则

- 原样保留：Docker 隔离、自包含 Qwen/Ollama/LangGraph、TRACE 1.2、recording/replay/fork、清理。
- 改接口复用：工具实现、状态序列化、初始化信封、CoverageInput 事实提取、通用 Fuzzer 执行队列。
- 降级为仅回归 fixture：Office V1 固定任务、12 组合、三载体、表达目录、安全/脆弱控制；永不进入
  V2 CoverageInput、Corpus、覆盖分母、候选竞争或等预算实验。
- 暂停：Office 专用 Campaign、RiskFrontier、G6、G5、变异子批和等预算实验。
- 最终退役：载体必选 TestCase、Office 固定候选生成器，以及只保护错误产品合同的测试。

迁移期间不直接删除旧模块。V2 通过同等职责验收后，按依赖顺序移除旧入口；不为保持错误兼容性而
扭曲 V2 设计。

## 8. 防止长线施工偷懒的控制规则

1. 一次只展开当前阶段的详细计划；下一阶段在当前阶段证据通过后再展开。
2. 每个小步只允许一个可观察结果，完成报告必须列输入、状态变化、输出、失败和验证。
3. 数据类、fixture 数量、测试数量和文档数量都不能单独作为完成证据。
4. 禁止使用 case ID、固定人员名、固定文件名或攻击关键词驱动通用逻辑。
5. 新增同类案例若仍需修改共享代码，立即停止并检查抽象是否错误。
6. Prompt、ToolSpec、Runtime、Oracle 不得各自维护一份冲突的权限事实；必须派生自单一世界状态。
7. 每阶段只运行具有判定力的聚焦测试；完整回归和真实 Qwen 只在阶段门运行。
8. 每阶段结束更新 HANDOFF 和 LOG，记录未完成项；不得把“代码存在”写成“行为通过”。
9. 架构假设被证据推翻时暂停，不通过增加例外、白名单或更多固定矩阵绕过。
10. 覆盖率或变异工作在阶段 8 前出现，视为范围漂移并停止。

## 9. 时间预算

这是完整场景重建，不按 MVP 估算。固定世界数据、部分可观察、多轮澄清和复合目标纳入后，建议预算
调整为 28-40 个有效工作日：阶段 0-1 为 4-6 日，阶段 2 为 6-8 日，阶段 3 为 5-7 日，阶段 4 为
4-6 日，阶段 5 为 4-6 日，阶段 6 为 3-5 日，阶段 7 为 2-4 日，阶段 8 为 2-3 日。

若时间不足，应减少验收故事中的实例数量或降低真实 Qwen 重复次数，不能删除身份权限、跨域因果、
四入口正交、固定世界质量、任务依赖、部分可观察、可信澄清、复合目标、事实 Oracle 或单一事实源
这些核心结构。
