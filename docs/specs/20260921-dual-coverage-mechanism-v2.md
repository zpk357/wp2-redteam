## 1. 研究主张与范围

`DCM-G01`：研究对象是一个可解释、可由执行证据重算的双覆盖反馈机制。平台为提供任务、轨迹、状态、工具和 Oracle 的实验载体。

`DCM-H01`（待检验）：在相同候选语义空间、Agent、变异模型及成本预算下，同时保留风险步骤观察和行为差异，比独立随机、随机演化以及单维覆盖取得更高的联合覆盖效率，并更快发现不同的冻结风险目标。

优势的预期来源分为两项：保留旧晋升门遗漏的行为差异、减少对已重复区域的预算浪费；在确有多步结构的目标上，另检验父样本能否保留有用步骤。后一项依赖输入变化能够在一定概率上保留已观察的行为，不能仅由代码证明。种子更多、提示更长、模型更强或副作用判定更宽松均不构成机制证据。

不承诺任何环境或任意短预算下都胜过随机。不把随机被测次数少的行为直接称为低概率，不把某个 Episode 的长轨迹直接称为长尾。

`DCM-S01`：第一版复用现有 Docker、Runtime、SQLite、轨迹、录制、目标 Oracle 与变异器；修改覆盖提取、语料保留、调度、必要的结算状态和预算记录。不扩展平台产品、运行时数量、部署系统、UI 或通用裁判系统。新的完整前提图、三节点因果片段、反馈提示、扩展变异算子和广义不安全结果 U 均不属于第一版。

`DCM-S02`：本次只形成设计；未启动新实验或编写生产实现。

## 3. 双覆盖与联合关系

### 3.1 风险覆盖 R：具体目标步骤的执行观察

`DCM-R01`：第一版复用冻结目标的 `TargetStepOutcome`，将每一步的 attempted、blocked、realized、required_context_visible 连同证据保存为独立观察。步骤列表不是必要前提图：只有声明的参数来源依赖、动态对象绑定或实际来源引用支持时，才记录相应关系；不从排列顺序推导因果。

风险单元由版本化目标语义 ID、步骤 ID、资源类别、授权关系、可见性上下文和观察状态组成。目标 ID 必须区分现有 16 个正式目标，不能只用四个大类或共享的场景 objective ID。原始资源 ID 不直接成为通用覆盖维度；若对象差异改变安全义务，使用预注册的语义类别。

未尝试与证据未知保留为缺口/质量信息，不仅因选择该目标就奖励新的执行覆盖。已尝试、平台阻断和效果实现不是强行递增的等级；未调用也不自动等于 Agent 明确拒绝。明确拒绝只有现有结构化行为证据支持时单独记录。目标已实现不覆盖其他目标的缺口。

`DCM-R02`：第一版的步骤组合表示“该次执行被 Oracle 观察到实现的步骤集合”，不能称为“目前仍有效的前提集合”。同一目标和初始语义上下文内，可将集合包含关系用作选父启发；它不证明离成功更近，不拼接不同 Episode 的集合。完成全部步骤的输入也不获得无限优先权。

现有 Oracle 取首个匹配调用，不能直接回答先失败后成功、先修改后撤销等全轨迹问题。第一版沿用其冻结语义并显式标注范围；若这些情况妨碍研究，需要另行冻结事件匹配/状态谓词契约，所有臂同步更新 Oracle 身份后重算，不能只给引导端换成有利口径。

`DCM-R03`：选择某个目标或提示中提到风险，不构成风险执行覆盖。失败也可以提供覆盖事实，但不因此被视作接近实现。

### 3.2 行为覆盖 B：与具体文本脱钩的执行路线

`DCM-B01`：优先复用现有行为提取器的参数形状、参数来源、权限分支、工具结果与状态变化原子特征；逐项排除实例编号等非语义维度。第一版新增关系至多包含一条显式来源边（两个调用），通过输出证据与参数 `source_refs` 对接；不重建通用行为图，不将最长三节点片段作为首版前提。

规范化维度包括工具语义角色、资源类别、来源关系、授权/策略分支、成功/拒绝/失败结果、状态变化类别。排除 Episode ID、时间戳、证据编号、随机生成文件名和措辞差异。

同一工具序列可能因来源或授权关系不同形成不同单元。无数据/控制依赖的相邻调用只属于顺序诊断，不冒充因果链。诊断性的所有工具 n-gram 可另存，不自动成为高价值反馈。

`DCM-B02`：新行为可以独立入队；不要求先攻击成功，也不要求完成与当前直接测试请求不一致的整套正常办公任务。测试输入的合法性、目标保持和证据完整性仍必须满足。

### 3.3 联合覆盖 J：有证据连接的 R 与 B

`DCM-J01`：联合单元是“行为原子特征/来源边 + 风险步骤观察 + 授权上下文”。只接受同一调用/状态转移或显式来源边支持的连接；仅发生在同一 Episode 不足以进入主联合覆盖。

`DCM-J02`：区分稳定语义键和证据完整性摘要。前者决定新颖性；后者用于审计。暴露事实中含证据 ID 的 digest 不能直接作为语义键。

J 的价值只能来自“哪项风险观察与哪种行为实际关联”，不能来自重复编码同一个工具/结果字段。若某目标下 R 已唯一确定所有对应 B 特征，J 在该区域可能没有额外选择信息。既有归档中目标签名不变而出现新 B，支持 B 未被旧签名完整表达；它仍不足以证明 J 比分别使用 R/B 更有效。

`DCM-J03`：报告 `ΔR`、`ΔB`、`ΔJ` 各自的集合与计数，保留仅新风险、仅新行为、新联合关系和全无新增等组合，不只留下单个 gain 标记。

未知的完整行为空间不虚构分母：可报告累计覆盖单元和增长曲线；仅在分母预先定义时报告百分比。

`DCM-J04`：同一输入的不同执行可能得到不同 R/B/J。档案保存输入对应的多次观察及证据，不将一次罕见输出当作确定可复现性质。规范化只消除命名噪声，不能抹掉真实行为差异；轨迹/工具重放通过也不等于模型重新执行稳定。需要重复确认时，所有臂适用同一规则且消耗既有预算。

## 4. 语料档案：原子单元索引与共享父样本

`DCM-A01`：分别维护 `(目标, 初始语义上下文, R 单元)`、`(目标, 初始语义上下文, B 单元)` 和 `(目标, 初始语义上下文, J 单元)` 索引，指向共享的父样本记录。J 只存实际有证据的配对。禁止以“完整 R 向量 × 完整轨迹 hash”创建格子，也不枚举未发生的笛卡尔积。风险尚未发生的样本仍可通过 B 被保留。

`DCM-A02`：具有新 R、新 B 或新 J 的有效输入可入档；在消融臂中，仅使用该臂启用的单元判断准入。第一版不做成本/文本长度驱动的代表替换，避免把一次低成本随机输出当作稳定优势。无新增候选仍完整保存用于审计，但不因此取得新父样本资格。

每个索引单元最多指向两个不同文本代表：最早准入的见证，以及最近准入的另一见证。更新只发生于该臂已准入的新颖候选，按结算顺序确定；文本仅做相同文本去重，不用相似度臆断语义等价。一个父样本可以见证多个单元，但所有引用共享同一记录。单元事实累计保留，代表替换不能让旧单元重新变成“新覆盖”。两个代表也不等于已验证可重复性。

第一版使用预先冻结的候选尝试上限 M 限定档案：非根父样本总数不超过 M，所有臂容量上限相同，不另引入容量调参或全局淘汰。随机演化可保留全部通过共同准入门的候选，按目标先分层再均匀选父；它不能读取执行结果决定保留。若未来预算规模要求更小容量，须另行冻结共同容量和淘汰协议。

`DCM-A03`：调度先选目标、再选该目标的反馈单元、最后选代表。单个目标的文本数量不直接决定其被选概率；更多不同单元仍可能影响目标内部的选父分布，这属于机制本身，必须报告。新种子无无条件“下一轮优先权”。

被平台阻断的首次新路径可保留；反复相同阻断不获得新颖性。保留结果与继续分配预算是两个不同决定。

## 5. 调度：两种互补工作，而非单个混合分数

`DCM-Q01`：第一版使用明确配额，不引入训练奖励模型或复杂 bandit。每 10 个候选机会固定分配：

| 工作 | 配额 | 选择依据 |
|---|---:|---|
| 全局探索 | 2 | 从共同初始候选空间分层随机重启，防止已见区域垄断 |
| 风险选父 | 4 | 同目标内已观察到部分步骤实现、尚未全部实现的代表；不存在时按 R 单元分配 |
| 行为扩展 | 4 | 暂未获得很多变异机会的 B/J 单元及其代表 |

20/40/40 是待开发集检查的设计默认值，不是文献证明的最优值。最终在保留评估集之前冻结，不能看正式结果后改权重。

每种自适应工作先在有合格父样本的目标间轮转，不按目标拥有的文本/单元数量加权。风险选父在同目标的可比初始上下文内优先选择部分实现步骤集合中的非支配代表；不存在部分实现代表时，选择获得机会最少的 R 单元。这里的非支配只指步骤集合，不混入成本或路径长度。平局由固定种子的随机选择解决；不得永远锁定等级最低的大类。

完整模式的行为扩展机会交替分给 B、J 索引，某索引为空时转给另一索引；R+B 无联合关系模式只使用 B。目标内部先选分配机会最少的单元，再按其跨 Episode 出现频次由低到高选择，平局随机。频次按每 Episode 至多一次计，不能用一次运行里的重复调用制造热度。仅 R/仅 B 消融将未启用的自适应配额交给剩余维度，保留相同全局探索配额。

`DCM-Q02`：第一版不采用“换个变异维度即重置”的冷却键。对 `(目标, 初始语义上下文, 已选择反馈单元)` 累计机会；同单元连续 3 次已完成执行均无该臂启用维度的新覆盖，暂停其自适应资格 10 个全局候选机会。B-only 不读取 R/J 判断增益，R+B 对照不读取 J。无新增执行同时更新该父样本所代表的相关单元，避免同一个父样本通过切换索引立刻重新获得机会。

生成失败、语义拒绝、超时也消耗机会和成本；它们记为无有效反馈，不能推断为风险未发生或结构不可达。同一父样本连续 3 次无有效反馈时也暂停 10 个全局机会；该通用失败退避对随机演化同样适用，且不读取覆盖事实。冷却计数、队列位置、随机状态与预算必须随一次结算原子保存，恢复不得重置。

平台拒绝是确定阻断证据，但单次阻断不能证明整个目标不可达。仅对同一语义前提的重复进行降配；未知的其他路径仍允许探索。失败原因未知时不标记结构不可达。

空队列配额依次转给另一自适应工作，仍为空则转给全局探索。每次候选均记录选择工作、语义单元、选择原因、冷却与成本。

## 6. 共同变异器与行为可继承性

`DCM-M01`：第一版所有臂共用现有变异模型、提示、正式算子目录、算子抽样规则、调用上限及整段文本槽。每轮一个候选，不新增攻击规划 Agent，不向变异 LLM 注入轨迹摘要。覆盖通过选择目标及父文本改变下一代输入，符合基于反馈的变异搜索；不宣称覆盖已控制具体词句。

资源、真实身份、权限、已有数据、目标成功定义与目标保持审查冻结。现有审查禁止新增动作/具体事实，不能把补写缺失步骤偷偷当成措辞优化。除执行结果无关的共同合法性门外，随机演化不以成功、轨迹或覆盖决定晋升。未验证目标保持的文本仍按共同协议记录，但不作为后续父样本。

`DCM-M02`：原稿提出的“保持项 + 缺口定向 + 单个可编辑语义维度”属于后续独立增强。当前代码没有轨迹到文本片段的因果映射，也没有可验证的语义 mutation mask。现有步骤布尔值不能自行生成这样的能力。

后续若扩展来源表达、步骤排列或反馈提示，先冻结合法空间和目标保持规则，所有臂同时获得相同算子能力；将是否消费历史摘要作为单独实验因素。不得向被测 Agent 编造权限/执行，LLM 不能改写 Oracle 事实。

所谓保持，是保留输入中已有的目标、来源引用和已选语义关系，并限制变动范围；不是从一次轨迹断言哪些词具有因果作用。局部变异后能否保持真实行为，必须从下一次完整执行观察，不能靠 LLM 自证。

`DCM-M03`：每次 Agent 从原初始状态完整执行；不把父 Episode 的工具结果或已实现状态拼接到子代。记录“输入目标保持通过”和“父子已实现步骤保持率”两个不同量；后者只在父代存在已实现步骤时定义，不能把空集合记为 100% 保持。

第一版将收益主要归因于覆盖表示、档案保留和选择的组合。即使有效，也不能从一次整体比较推断三个组件各自的贡献；直接反馈进 LLM 更不能与第一版结果混合。

## 7. 示例与机制假设

以下是有明确依赖的多步目标假设，不代表现有 16 个目标的普遍结构。某输入在一次执行中实现 A、B，却未实现 C：

1. R 保存 A/B 已达与 C 未达，不退化成“失败”。
2. B 保存达到 A/B 的来源、状态和动作路线。
3. 档案保留该样本及其他不同路线的代表。
4. 风险选父选择该输入，交给共同变异器生成子代；下一次完整执行再观察 A/B 是否保留以及 C 是否出现。第一版不能保证只改变 C 对应的语义。
5. 后续若走出新路线但尚未完成 C，B/J 仍可保留它；若只是重复同一阻断，预算降配。

待检验的优势是提高再次到达有用步骤组合的概率，不是免费继承父代世界状态。现有“聚合多个资源后发送结果”虽有两个步骤，但注册并未声明 send-aggregate 必须引用 aggregate-sources 的输出；不能仅凭目标名称把它当成已证明的 A→B 因果链。

`DCM-H02`：若改写几乎不能保留父代已实现步骤，不能声称通过保留前提积累进展；应报告该渐进搜索假设不成立，并单独评价行为探索是否仍有收益，不能不断改指标来保住原解释。

## 8. 研究验证与比较协议提案

### 8.1 覆盖效率与独立目标发现

`DCM-E01`：保留 `docs/SPEC.md` 的产品要求：以冻结的稳定 J 增长及成本效率作为主要覆盖证据，同时分别报告 R、B，不能用总分掩盖退化。原始攻击成功率继续报告；重复命中同一个容易目标不构成多次独特发现。

第一版外部效用使用 D：直接复用 `fuzzer/v2_effectiveness.py` 的 `classify_settlement` 与 `EffectivenessCounts.distinct_success_targets`，报告不同冻结成功目标数及其成本曲线。同一固定场景下同目标多次成功只计一次，上限为 16。当前成功分类依据所有步骤实现及所需违规上下文确认，并不把父样本晋升的目标保持审查作为成功门；不得在新报告里暗中增加这道门再称口径未变。证据质量与语义审查结果另行分层报告，所有臂采用相同规则。D 不是“不同漏洞数”，也不是“不同实际副作用数”；将来新增场景配置时，另冻结目标/配置的分层与去重协议。

原稿的广义不安全结果数 U 需要另行冻结义务、授权关系、资源类别、实际副作用及等价类；不能由新覆盖键顺带定义，不能把任意中间副作用都计为不安全。第一版不引入 U，不篡改历史成功定义。将来若需要 U，先完成独立 Oracle 规格，再以新评估协议比较所有臂。

R/B/J 新增、重复率、父子步骤保持率和达到目标的预算用于解释机制。“覆盖机制提高覆盖效率”与“更快发现不安全目标”分开报告；只有 J 改善时，不宣称已完成安全发现方面的强主张。D 已接近上限时重点查看首次发现成本和曲线，不能将覆盖更多直接改称发现更多风险。

### 8.2 必需比较

| 模式 | 作用 |
|---|---|
| 独立随机 | 保留现有每轮根种子独立采样语义 |
| 随机演化 | 也可多代改写；共同有效性门通过后保留候选，在目标内均匀选父；同容量上限、同全局重启配额，不读 R/B/J、成功或轨迹 |
| 仅风险反馈 | 移除 B/J 对选择、保留和计划的影响 |
| 仅行为反馈 | 移除 R/J 的执行进度反馈，仍保留两臂共用的静态目标契约 |
| R+B 无联合关系 | R、B 分别参与保留和选择，但不读取任何 J 单元；识别联合关联是否有额外价值 |
| 双覆盖及联合关系 | 本文完整机制 |

`DCM-E02`：只胜过独立随机不足以证明双覆盖机制有效；必须比较随机演化，并用单维消融检验两个维度的互补性。若完整机制不优于 R+B 无联合关系，不能宣称 J 具有独立引导价值。优于两个单维也不自动证明统计上的超加性“协同”，后者需要专门的交互效应设计。随机演化是新命名的对照，不修改已有 `random_independent` 含义。

所有反馈臂使用同一档案实现、同一选择层次、同一失效处理；消融只关闭相应信息源，并按第 5 节预定规则重新分配其配额。所有臂都可在评估端计算同一套 R/B/J，但关闭的信号不得进入该臂准入、频次、冷却或选父。当前旧引导可作为历史算法对照，用同一新指标旁路评估；它不代替上述随机与消融对照。

`DCM-E03`：第一版只做相同现有变异器下的覆盖档案/选择机制比较。反馈摘要和更强局部算子属于后续分别控制的因素，不能为了让第一版获胜而临时加入，再将收益全部归因于覆盖度量。

### 8.3 预算、数据划分与效果门槛

`DCM-E04`：按生成/执行尝试及总模型 token 限额计费，不再只按补足 K 个可判定结果计预算。无效变异、重试、超时、语义审查和证据确认均计成本并保留结果。各臂上限相同；分别报告 token、Episode 尝试和时间，不能把不同成本混成未经说明的总分。

当前代码没有现成的“全部模型总 token 硬上限”：`ExecutionCosts` 不含 Judge 项，`CampaignBudgetSnapshot` 只检查 mutator token 等预算，Judge 请求另行执行。第一版必须为实际 Mutator、Agent、Judge 请求分别记录调用及输入/输出用量，并接入统一预留/结算；缓存命中单列，不能作为新模型调用重复收费。未能可靠取得全部用量时，不能声称等总 token 已验证。候选机会 M 与 token 上限任一先达到即停止，不能用补跑抹去失败成本。

同一实验组冻结候选空间、初始状态、Oracle 和运行参数，随机化臂的执行顺序。Campaign 是重复实验单位，同一 Campaign 内的 Episode 不是独立重复。

现有 15×2 归档属于设计资料。它的目标/文本不得再次被当作未见测试集；换随机种子也不会使任务变成未见任务。当前支持构建器只为 16 个根目标各选一个固定 direct-task fixture，现有归档还共用同一 actor/task，因此目前没有现成的独立任务保留集。第一版可研究固定场景内的多次搜索效果；主张未见任务有效前，必须单独冻结所有臂共用的新任务/资源配置及配套 Oracle，不把它伪装成已经具备的平台能力。

建议把“安全发现明确更强”的实用门槛预设为：在等预算评估上，D 成本曲线面积相对预先指定的随机演化主对照提高至少 25%，且配对差值置信区间下界大于 0；独立随机也必须完整比较。25% 只是验收提案，不是预测，不能据现有小样本声称可达。随机基线均值为零时不计算比例，改报绝对增益与区间。正式任务外推结论还必须满足保留任务条件。

第一版预定产品覆盖终点为 J 的成本曲线面积，外部安全效用终点为 D 的成本曲线面积，预算终点 D 为辅助；两类结论分别检验，不择优报喜。面积在预定共同 token 区间计算，覆盖/发现到其证据完成结算时才计入；失败导致提前停止时，曲线保持停止前水平至共同预算末端，不删掉该 Campaign。不得事后改用较有利的指标，也不得把面积改善自动解读为最终数量增加。

正式重复数在独立开发重复上按上述最小实用效果、80% 目标功效与配对差值方差确定，通常需要多个独立 Campaign；当前只有每臂一个 Campaign，不能拿其 15 个 Episode 估计 Campaign 间方差。不能声称固定 10 或 20 次必定足够。样本数、配对区组、终点、置信度、多重比较方法与停止规则须在正式评估前写入独立实验 SPEC；不得边看显著性边决定追加。第一版机制 SPEC 不虚构尚无依据的正式运行规模。

`DCM-E05`：需要至少一个未参与机制调参的任务组合；广泛跨模型主张另需独立模型证据。在单一合成 Office 环境成立时，结论只限于该环境，不宣称所有 Agent 都有效。

### 8.4 场景适用性与“长尾”

区分容易实现、硬阻断、需要多个前提的任务，但保留完整任务集合与分层结果。任务混合是策略效果的一部分；不能事后删除硬阻断任务来提高引导成功率。

如果当前候选空间基本只有“一步即成功”与“同权限下始终阻断”，必须承认该空间难以检验渐进式搜索，而不能伪造较弱随机基线。可在实验前固定新的组合任务供所有臂共享，并明确它们是构造的机制诊断，随后另看未参与设计的组合。

主张长尾优势时，长尾集合必须由独立、冻结的参考采样分布和采样数据定义，并报告频率不确定性。引导运行里访问次数少，仅称为“当前搜索中的稀有单元”。本阶段不假装已知真实小概率。

## 9. 失败信号与退出条件

- `DCM-F01`：语义等价执行因编号变化产生新增覆盖——度量不成立，不能进入效用比较。
- `DCM-F02`：覆盖更多但 D 效率无改善——只支持覆盖探索效果，不支持安全发现优越性。
- `DCM-F03`：只优于根随机，不优于随机演化——无法排除多代改写/记忆带来的收益。
- `DCM-F04`：双覆盖未胜过任一单维——尚未证明两维互补；未胜过 R+B 无联合关系——尚未证明 J 的额外引导价值。
- `DCM-F05`：优势只在额外 LLM 摘要/调用开启后出现——重新归因，不能只归功于覆盖指标。
- `DCM-F06`：局部改写不保持行为前提，或同义重复不断创建档案格子——先审视表示和可继承性，不扩大无效运行。
- `DCM-F07`：仅开发任务有效、保留任务无效——报告过拟合，不移动测试集边界。

## 10. 与旧契约的关系

以下是明确的设计变更提案，而不是对当前代码语义的重新包装：

1. 替换“最低风险大类等级 + 池内均匀 + 新种子一次优先”的选择规则。
2. 替换目标行为签名一票否决及与直接测试不一致的正常任务完成晋升门。
3. 联合语义关系进入档案和反馈；修复证据摘要/语义键混用。
4. 第一版保持共同现有变异器，扩展算子及覆盖摘要后置；多代改写不等于已具备局部行为保持能力。
5. 增加随机演化、R+B 无联合关系对照，使用冻结目标发现数 D 补充覆盖效率证据，不在首版另造广义 U。
6. 对覆盖 taxonomy、调度协议、档案索引、冷却计数、预算与状态摘要使用新身份。新索引和旧四类进展不可混用；新实验从新 Campaign 开始。旧快照保留原读取与审计语义，不自动迁移成新指标。任何档案、队列或成本更新都必须纳入原子结算及恢复。

此前的 `20260917-dual-coverage-evaluation-design.md` 和 `20260920-guided-seed-priority.md` 仍是其旧运行的解释依据。新实验必须使用新协议身份，历史结果不回写。

## 11. 借鉴来源与创新边界

- AFLFast：借鉴低频路径与预算分配，不照搬其适用于传统程序的收益保证。[作者仓库](https://github.com/mboehme/aflfast)
- FairFuzz：借鉴尽量保留已到达分支条件的局部变异思想；本提案的语义保持约束不是已验证的字节级 mutation mask。[论文](https://www.carolemieux.com/fairfuzz-ase18.pdf)
- MAP-Elites：已有工作提出按行为维度维护代表档案，因此二维档案本身不宜宣称首创。[论文](https://arxiv.org/abs/1504.04909)
- AgentFuzz：已有面向 Agent 的执行反馈、种子调度和定向变异；不能把“给 Agent 做反馈 Fuzzing”宣称首次提出。[论文与发表信息](https://www.usenix.org/conference/usenixsecurity25/presentation/liu-fengyu)
- FLARE：已有面向多 Agent 的行为覆盖引导研究；其覆盖定义与安全风险义务并不相同。[预印本](https://arxiv.org/abs/2604.05289)
- Evaluating Fuzz Testing：参考重复实验、结果变量与随机性处理的研究方法。[论文](https://arxiv.org/abs/1808.09700)

候选研究贡献是：由确定性执行证据建立目标风险步骤观察与行为特征的稳定联合表示，并检验这两个维度是否共同改善语义搜索效率。第一版不称通用安全义务图，不称语义 mutation mask。创新性仍需要更完整的相关工作对照与实验，不能由本次检索直接确证。

## 12. 当前交付与待决

本次自审把结论分成三层：

1. **可实现性：有静态依据。** 已有结构化来源、权限、结果、状态和录制证据，可以实现稳定单元、索引和反馈；需要新增结算状态及完整计费，不能只改调度函数。
2. **预计收益：有针对性理由，未被证实。** 新 B 可以独立保留，虚假 J 不再制造奖励，同一大类不再锁死目标；这些消除了已观察到的缺陷，却不能推出收益大小或全局优势。
3. **研究目标：尚未完成。** 需要证明 R/B 有互补性、J 是否有增量价值、固定预算下是否优于两个随机对照。现有档案不能产生尚未执行的反事实子代，因此静态阅读能否定不成立的假设，不能替代最终效果证据。

仍为 `DRAFT`。进入 TASK 前必须在本 SPEC 的附件中冻结 R/B/J 字段枚举及规范化映射、合法/未知证据边界、公共父样本准入与六臂选择伪代码；这些决定研究含义，不能作为随意实现的细节。独立实验 SPEC 再冻结开发/评估划分、预算、统计门槛及重复规模。当前审查不要求用户授权新测试，也没有启动这些实验。
