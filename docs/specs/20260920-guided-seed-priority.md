# 引导臂新晋升种子优先探索规格

状态：`APPROVED`（用户于 2026-09-20 确认"没有问题就开始"）
日期：2026-09-20

## 目标

让 `coverage_guided` 的覆盖反馈在后续父样本选择中产生可观察、可复算的一次性影响：新晋升种子加入后，在下一次从该种子池选择父样本时优先获得一次变异机会。种子优先只改变选择顺序，不增加总预算、不改变候选空间、不改变变异算子和攻击成功定义。

## 非目标

- 不把攻击成功反馈接入选择；本规格仍称为覆盖引导。
- 不改变 `random_independent` 的独立随机语义。
- 不增加权重模型、奖励函数、LLM 判分或新的数据库表。
- 不保证引导攻击成功率高于随机。
- 不把历史 Campaign 事后改判为使用了本机制。

## 术语与规则

- **新晋升种子**：本代结算后依据现有晋升契约新加入引导语料池的种子。
- **优先队列**：由尚未获得本次优先机会的新晋升种子组成，持久化顺序按晋升事件的稳定顺序确定。
- 每个新晋升种子只获得一次优先机会。被选出并成功生成对应准备记录后，从队列移除；恢复时不得重复发放。
- 若同一结算产生多个新种子，按现有稳定排序（不得依赖集合或数据库非确定顺序）逐个入队。
- 下一次需要选择父样本时，若队列非空，取队首；队列为空时沿用现有均匀随机选择。
- 独立随机臂不读取、不维护、不消费该队列。

## 公平性与可观察性

两臂总 Episode 目标、调度上限、执行上限、模型、镜像、场景、种子和 Oracle 保持原有冻结口径。引导臂优先机会从自己的既有预算中消耗，不追加预算。每次选择必须记录来源：`new_seed_priority` 或 `uniform_pool`，以及被选种子的 ID、入队原因和队列长度；随机臂只能记录 `uniform_pool`。

## 验收标准

- 新晋升种子在队列非空时，下一次引导选择必定优先于普通池选择。
- 多个新晋升种子按稳定顺序各获得一次优先机会。
- 队列耗尽后，选择行为恢复现有均匀随机语义。
- 重启或幂等恢复不丢失队列、不重复发放优先机会。
- 随机臂没有跨 Episode 晋升队列或优先选择分支。
- 现有总预算、候选内容、变异算子、结算与评分口径保持不变。
- 选择记录可以离线重建每个晋升种子的入队、消费和父样本命中关系。

## 待确认

本规格需用户确认后，才能进入 `READY` 任务并实施。优先机会的消费点暂定为“选择成功并生成准备记录”；若准备被拒或执行失败，不补发第二次优先机会，避免同一种子垄断预算。

## 实施决定（2026-09-20，实施前定稿）

1. **消费点**：优先机会在**代次结算时消费**（Episode 结算或非 Episode 关闭都算），不是"生成准备记录时"。
   理由：结算是一次原子写入且可幂等重放；准备被拒绝、执行失败或 Controller 中途重启都不会
   再补发第二次机会，符合"不补发"与"恢复不重复消费"。队列的消费以该代次 allocation 的
   父样本选择收据为准，重复提交同一结算不重复删除。
2. **命中范围**：优先命中同时确定**风险方向与该种子本身**。`GenerationAllocation` 要求方向收据
   闭合到 `risk_type`，而被晋升种子自带所属池，因此优先命中就是"该种子的池 + 该种子"。
   方向与父样本两个收据都使用新的 `new_seed_priority_v1` 策略（单选项、draw=0），
   可复算且与均匀随机收据可区分。
3. **digest 兼容**：队列为空时排除出 Campaign state 的 digest payload。这样历史 Campaign
   （无该字段）仍能通过校验与读取，新 Campaign 的非空队列进入 digest。
4. **状态重建接口**：`build_campaign_state` 新增必填的队列参数，所有调用点必须显式传递；
   忘记传递会立即报错，而不是静默丢队列。
5. **独立随机臂**：不读取、不写入、不消费队列；由策略判定与测试共同保证（见验收标准）。
