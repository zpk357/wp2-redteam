# 项目入门 PPT 规格

状态：`DRAFT`

## 1. 目的与受众

- `PPT-OBJ-01`：帮助不了解项目的听众建立可复述的整体心智模型：项目要解决什么问题、一次测试如何运行、为什么要同时看风险和行为、反馈如何进入下一轮探索。
- `PPT-AUD-01`：主要受众是项目外部的技术同事，不要求读过仓库代码。
- `PPT-USE-01`：支持约 10 分钟现场讲解，也能脱离代码独立阅读。
- `PPT-TONE-01`：使用清晰、克制、教学式表达，不用宣传口号，不把研究假设写成结论。

## 2. 已确认内容范围

- `PPT-SCOPE-01`：介绍项目背景、目标、核心对象和端到端测试闭环。
- `PPT-SCOPE-02`：重点解释“风险维度覆盖率 + 行为档案覆盖率”的双重指标，以及由同一 Episode 证据建立的联合覆盖关系。
- `PPT-SCOPE-03`：用一个有证据标注的 Episode 说明：真实工具效果/状态变化 -> 行为单元、风险单元、联合单元 -> 覆盖增量分类 -> 下一轮选择/变异。
- `PPT-SCOPE-04`：展示一次已记录的两臂运行读数，说明 `coverage_guided` 与随机模式的比较口径和当前读数能支持到什么程度。
- `PPT-SCOPE-05`：用一页说明当前能力边界、未完成项和阅读时应避免的误解。
- `PPT-SCOPE-06`：页面使用中文；不加入讲者备注。

## 3. 双重覆盖的内容契约

- `PPT-COV-01`：行为覆盖必须解释为 Agent 实际走过的可追踪路径和动作，例如工具调用、调用顺序、授权/策略分支、成功/拒绝/重试、状态变化和终止原因。
- `PPT-COV-02`：风险覆盖必须解释为测试触达的安全风险及其阶段，例如风险目标、授权上下文、风险载体、被阻断/尝试/已实现，以及由 Oracle 支持的风险事实。
- `PPT-COV-03`：联合覆盖必须解释为同一 Episode 中风险与行为的关系，示例形式为“行为路径或状态转移 × 风险类型/目标 × 风险阶段 × 授权上下文 × 执行结果”。
- `PPT-COV-04`：必须明确保留四类局部结果：仅新行为、仅新风险、新行为与新风险形成新联合关系、三者均无新增。
- `PPT-COV-05`：必须明确说明“没有新增”是相对于当前覆盖账本和作用域的判断，不等于模型没有执行动作，也不等于没有发现风险。
- `PPT-COV-06`：必须明确说明覆盖只从真实轨迹、工具结果、状态差异和确定性 Oracle 提取；提示文本或模型自述不能单独构成风险命中。
- `PPT-COV-07`：必须明确说明 `coverage_guided` 消费跨 Episode 覆盖反馈来影响父样本/方向/变异位置或内容；随机基线不应消费该反馈。若当前代码或实验记录存在偏差，页面必须如实标注。

## 4. 事实、证据与边界

- `PPT-EVID-01`：事实优先来自 `docs/SPEC.md`、`README.md`、`docs/current-state/`、已批准的需求/任务文档和已记录的运行报告；允许补读代码核对少量细节，但不把代码片段放入主叙事。
- `PPT-EVID-02`：真实运行读数优先引用 2026-09-27 `summary-delivery-enc-01` 两臂记录：引导 16/16 结算、`W/F/Q = 4/12/0`、`W/(W+F)=25.0%`；随机 15/15 结算、`W/F/Q = 3/12/0`、`W/(W+F)=20.0%`。读数必须附带“单对、每臂约 16 个机会，不能支撑正式统计优越性结论”的限定。
- `PPT-EVID-03`：Episode 机制示例可使用 2026-09-27 本地机制验收中有正式 Oracle 和覆盖账本的脚本模型样本；页面必须标注“机制验收示例，不代表真实模型攻击率”。
- `PPT-EVID-04`：若使用项目 README 中的 `audience-scope`、`data-release`、`W/F/Q` 或 7 起越界读数，必须解释判定来自真实提交工具效果，`Q` 表示证据不足以判定，不能把 `W=0` 直接解释为安全。
- `PPT-EVID-05`：必须明确区分产品长期规格与当前代码/实验现状。联合覆盖、随机基线公平性、正式统计协议、Judge 置信度加固等未完成或存在差距的部分不能被页面写成已完成能力。

## 5. 非目标

- `PPT-NON-01`：不讲 Python 类、文件路径、函数调用、数据库表结构或容器构建细节，除非一个概念无法用业务语言解释。
- `PPT-NON-02`：不把单一综合分数、单一 `coverage_gain` 或最终回答质量分数当成双重覆盖指标。
- `PPT-NON-03`：不宣称覆盖率引导必然优于随机模式，不把一次运行读数包装成统计结论。
- `PPT-NON-04`：不宣称 Judge 已完成校准、漂移监控和人工复核闭环。
- `PPT-NON-05`：不展示可用于攻击未授权目标的操作步骤、真实凭据或敏感数据。

## 6. 预期页面结构

预计 9 到 11 页，具体页数在任务阶段冻结：

1. 标题与一句话定位：行为轨迹级度量与覆盖率引导的自动化红队测试。
2. 为什么需要它：只看最终回答会遗漏路径偏移和模式坍缩。
3. 一次测试长什么样：Scenario、Test Case、Episode、Trace、Oracle、Finding 的关系。
4. 完整闭环：候选/变异 -> Agent 执行 -> 轨迹与状态 -> Oracle -> 覆盖 -> 下一轮。
5. 行为覆盖：从“做了什么”建立行为档案。
6. 风险覆盖：从“触达了什么风险、处于什么阶段”建立风险维度。
7. 联合覆盖：同一 Episode 如何把风险与行为连起来，并展示四类覆盖结果。
8. 一个 Episode 的证据链：用示例逐步标注行为单元、风险单元、联合单元和反馈。
9. 两种探索模式：`coverage_guided` 与随机基线的唯一原则性差异和公平比较条件。
10. 一次真实运行读数：W/F/Q、交付率和结果解读边界。
11. 当前状态与记忆点：已实现、未完成、听众应带走的三句话。

## 7. 视觉与可读性要求

- `PPT-VIS-01`：以流程图、对照图和少量数据图为主；不用代码截图作为主要视觉。
- `PPT-VIS-02`：双重覆盖使用两种稳定、可区分的视觉编码，并用第三种连接样式表达联合关系；颜色不能单独承担语义。
- `PPT-VIS-03`：流程方向清晰，连接线不穿过文字；每页只保留一个主要结论，避免卡片堆叠和密集小字。
- `PPT-VIS-04`：所有数值图表同时显示分母、样本规模和“当前证据边界”脚注。
- `PPT-VIS-05`：使用一致的中文字体、字号层级和页脚来源标识；页面内容必须在桌面投影尺寸下可读。

## 8. 验收标准

- `PPT-AC-01`：不了解项目的技术听众能用自己的话说明项目为何保存完整轨迹，而不只是最终回答。
- `PPT-AC-02`：听众能分别解释行为覆盖、风险覆盖和联合覆盖，并说出至少一个各自的例子。
- `PPT-AC-03`：听众能区分四类覆盖结果，理解“仅新行为”不等于“发现新风险”，“仅新风险”也不等于出现新路径。
- `PPT-AC-04`：听众能沿着示例 Episode 说出证据如何形成覆盖增量，以及反馈如何影响下一轮选择/变异。
- `PPT-AC-05`：读者能正确解释一次真实运行中的 `W/F/Q`，不会把 `W=0` 自动当成“模型安全”。
- `PPT-AC-06`：所有产品结论、当前状态、实验读数和未完成项都有来源或明确的证据等级标注。
- `PPT-AC-07`：页面无代码细节堆积、无不可解释的总分、无把研究假设写成结论的措辞。
- `PPT-AC-08`：生成后通过渲染逐页检查，确认无文字溢出、重叠、裁切、图表误读或来源脚注缺失；运行 `git diff --check`。
