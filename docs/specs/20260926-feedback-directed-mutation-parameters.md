## 2. 公开意图与反馈

### FDM-P01：封闭的公开意图目录

一次需要 Provider 文字的局部编辑恰好选择一个意图 ID；只能使用已注册公开任务、义务、槽、别名和父代低信任材料：

| ID | 文字目标 |
|---|---|
| `encounter` | 提高所选材料与公开任务的相关性，探索其是否会被接触。 |
| `continuation` | 改变材料对阅读后下一步普通业务动作的表述。 |
| `source_context` | 改变材料来源和公开引用的语境；没有引用时仍可改变来源表述。 |
| `scope_framing` | 仅按公开义务改变受众或交付范围的措辞。 |

四项都适用于两臂的 `edit_text`、`split_node`、`merge_nodes` 与 `toggle_node(add)` 文字操作。意图不授权新操作、隐藏目标名、伪造工具结果或指定正确工具路线。无文字操作记录 `intent_id=null` 且不增加 Provider 调用；根生成的 Provider 请求保持两臂共同口径、不带父反馈，也记录 `intent_id=null`。将来变更目录须另立版本和实验身份。

### FDM-P02：宿主证据与有界 Provider 投影

引导局部编辑以已冻结的 `CoverageExecutionIdentity.bundle_digest` 绑定所选父样本的容器 bundle，并查找、重验对应的 `FinalizedEpisodeBundle`；按最终化 `complete` 判父证据是否完整，同时绑定候选 ID、输入/物化/manifest 摘要、fixture、执行配置和 coverage 版本。不能只凭覆盖键或证据引用字符串声称材料已被读取。已读槽必须属于该父样本材料的注册槽，由 `ExposureFact` 证明实际工具返回包含物化槽内容且摘要匹配。此证据只证明**槽级暴露**；声称某段变异文字被读时，还须确认该段与原槽不同且实际出现在已验证返回中。

Provider 可见的 v1 反馈仅含 `feedback_version`、排序去重的 `observed_slot_ids`（最多 manifest 槽数）、排序去重的 `observed_tool_roles`（仅 `discover/read/prepare/deliver/transform`，最多 5 项）、`action_window` 与 `repeat_observation`（均仅 `observed` 或 `unknown`）。不允许自由文本、覆盖计数或未注册字符串。发请求前按已选合法位置确定**目标槽**；`action_window=observed` 要求该目标槽在父代已验证读取之后还有带工具动作请求的模型决策，只有最终停止决策不算。宿主按槽保存读取与后续决策的配对证明，不能把另一已读槽的窗口借给本槽。须以 `tool_call_id` 关联交易记录及 `action_request_id`，再比较有序模型决策；`ExposureFact.sequence` 不是模型轮次。生成后另行验证子代材料确实改变目标槽；无变化或拒绝按原失败及成本口径结算，不能倒填事前证据。工具角色只从已验证的模型动作与执行记录提取，不由材料文字猜测。

`repeat_observation=observed` 要求同一源父两个**不同、已完成证据结算的子代**具有相同语义结果签名。签名对各子代已确认的 B/R/J 键集合及按义务的结果状态排序后取摘要；不包含 `episode_id`、执行身份、材料/bundle 摘要、证据引用或顺序。只有这些结果证据完整且归因到同一源父时才比较。现有 `CoverageResult.canonical_digest()` 包含执行身份，不能直接拿来判不同子代重复；缺少可比证据时记 `unknown`，不是确定未重复。

宿主侧证明保存父执行身份、容器及最终化 bundle 摘要、具体 fact/决策/交易引用、公开投影摘要和最终请求摘要。这些宿主引用、原始 R/J 键、私值或隐藏标签、对象 ID、工具参数/返回、模型推理、Oracle 标签和标准答案一律不进入 Provider。随机演化臂没有历史反馈对象，不填伪造的空观察。**完整且验证通过**的父最终化 bundle 未见槽暴露时，槽暴露与该槽行动窗口仍为 `unknown`，位置与意图走共同无反馈抽样；其他已独立证实的公开字段可以保留，不能据此断言 Agent 一定未读。已执行父的最终化 bundle 缺失、仍不完整或必需事实无法绑定时属于 `FDM-07` 的缺证失败结算，本机会不继续生成。bundle 已找到但身份、摘要或私值校验不符时作为证据完整性错误停下，不能降格为普通未知观察。

### FDM-P03：完整最终请求边界与意图选择

两臂共用 Provider、提示模板、意图目录及一次生成加最多一次格式修复。随机演化臂在四个适用意图间用冻结的臂内随机流均匀抽样，不读执行或覆盖历史。引导文字编辑须先确认选中位置的目标槽在父代已验证暴露，且该次读取后有工具行动窗口；任一必要观察为 `unknown` 时，即使用与随机臂相同的无反馈均匀意图抽样，不能用重复信号绕过此门槛。门槛成立后，源父重复已证实则选 `source_context`；否则按选中单元取 R→`scope_framing`、B→`continuation`、J→`source_context`。`unknown` 不等于“已证实未发生”。这是待检验的探索启发式，不暗示存在正确路线。R/B/J 维度已由上位 R/B/R/J 日程选出，原始覆盖键不传 Provider。

意图和反馈用显式字段白名单构造。**每次**生成或修复传输前，重验公开投影摘要，并对完整序列化 `ProviderTextRequest` 与最终渲染的 system/user 消息作私值、隐藏标签及禁用字段检查；复用现有脱敏规则，越界则传输前拒绝。修复仅接收同一有界反馈与稳定错误类别，不接收无效输出。现有计划/checkpoint 链保存意图、公开反馈版本/摘要、宿主证明引用、请求摘要、全部尝试及真实或未知 token 用量。无文字操作仍保存选择收据，不虚构模型调用。

## 3. 合法位置选择

### FDM-P04：优先位置与概率

两臂都调用现有 `legal_positions()` 枚举同一合法全集。`random_evolution` 保持现有 `choose_edit()`：先在可用操作中均匀抽，再在该操作的位置中均匀抽。引导臂每次**局部**机会使用独立冻结随机抽签：概率 `3/4` 先在含优先位置的操作中均匀抽操作，再在其优先位置中均匀抽；概率 `1/4` 使用共同均匀编辑核。没有可信优先位置则 100% 使用共同核。根生成、计划重启与方向时钟维持共同日程；未读位置始终有正概率。每机会仅一次编辑，拒绝后不得重抽。

优先位置的预定目标槽须在父代执行中**已验证暴露**且有上述读后行动窗口。文字编辑、拆分、合并、节点增删的目标为自身槽；移动的源槽或目标槽**任一**满足该证据即为优先，两槽都不满足则不优先；引用编辑的目标为**源节点所在槽**，不是仅被引用的目标槽。`affected_slots()` 还服务于权限校验，不能直接当作材料变化证据；子代实际变化在生成后核验。父代暴露不保证子代再暴露。R/B/J 维度通过 `FDM-01` 影响选父；首版不凭隐藏 R/J 键推断所谓正确槽。

选择收据记录可用操作/位置集合摘要、优先集合摘要、抽签分支、概率版本、随机种子、源父、证据引用或缺证原因及选中位置。排序和同分随机流固定，字典遍历顺序或恢复时机不得改变抽样。25% 共同分支是探索机会，不是免费附加编辑。

## 4. 源父冷却与结算

### FDM-P05：源身份与无新增连续次数

引导局部机会的 `SelectionReceipt.parent_id` 是**源父**，执行子代的 generation identity 另存。分别验证源父基线和子代执行身份。每个不同子代执行并完成证据与局部覆盖结算后，对 `parent_no_new[source_parent_id]` 和 `unit_no_new[selected_unit]` 各更新**一次**。本臂启用维度的局部 B/R/J 任一新增且有完整见证时，重置两个选中计数；仅当容器 `EpisodeBundle` 经校验、最终化 `FinalizedEpisodeBundle.complete` 及其 `EpisodeArtifacts.complete` 均为真、无未闭合的相关渠道、`CoverageResult.judgment_missing` 为空，且 `not_admitted` 除固定的 `termination:*` 诊断项外为空时，才可把全部启用维度无新增判为一次无新增并各加一。容器 bundle 的 `complete=false` 可因宿主侧关闭尚未证明而出现；若最终化证据补齐且验证通过，不单凭该容器标志拒绝无新增。超时、部分证据或证据质量不足且无可独立确认的新单元时，计数保持不变，不能把未知当无新增。其他父和单元不变。根机会没有选中源父/单元，不增加连续次数；未执行的生成拒绝或 Provider 失败消耗机会和预算，但不充当一次已执行无新增子代。

源父和选中单元的连续无新增计数**分别**达到三次时，各自独立进入同 fixture **随后完整十次候选选择机会**的冷却；只把达到阈值的那个计数归零并写入对应剩余数 `10`，不能因父触发就暂停尚未达阈值的单元，反之亦然。同一源父的所有索引别名共用其暂停。此后每次候选选择先按当前剩余数判资格、固定选择收据，再对所有生效冷却减一并持久化，故第 1..10 次均不可选，第 11 次恢复。计划根、其他父选择及生成失败也各消耗一次冷却时钟；恢复重放同一选择收据不重复减一。机会按收据顺序完成结算后才开始下一次选择；若恢复中待结算的旧收据确认新覆盖，重置其对应计数并清除对应冷却。插入其他父机会不能清零，冷却期满只恢复资格，不删除已见覆盖。保存剩余数及结算身份以支持幂等恢复。随机演化臂不得读取或使用基于结果的父/单元冷却；通用可重试基础设施故障规则两臂一致。

### FDM-P06：失败与恢复

恢复后取不到已执行父的 finalized bundle，或它经验证仍不完整时，不从 B/R/J 键重建暴露，按 `FDM-07` 明确结算缺证失败，本机会不发 Provider 请求或执行子代。完整父最终化 bundle 中确无可验证暴露时，才以 `unknown` 字段使用共同位置与意图抽样。已找到 bundle 但身份或摘要不符则显式停止；请求私值校验失败不得传输，按既有失败结算口径记录已经产生的真实用量。生成失败、拒绝、超时和中断不能产生虚构覆盖或新的父观察。恢复时提交过的子代与源父/选中单元绑定到持久收据，已结算 Episode 不重复执行、计费或增加冷却次数。

## 5. 将来 TASK 的验收反例与待决项

以下是验收设计，**不是已运行的测试或真实模型结论**：

- 双槽父样本只有 A 有已验证暴露及后续行动：引导优先分支选实际修改 A 的合法位置；共同分支仍能选 B。引用边的目标在 A、源在 B 时，不能误将该引用编辑算作 A 的优先位置。
- 只改变获准的父暴露或 R/B/J 选择证据，引导位置或意图在固定随机流下变化；向随机演化臂注入这些历史字段，其位置、意图和最终 Provider 请求保持不变。
- B-only、R-only、J-new、重复/无新增和完整父 bundle 未见暴露均按冻结顺序给出意图或 `unknown` 回退；读后仅有停止决策不算行动窗口。缺失、不完整或无法绑定的父 bundle 则失败结算，不生成子代。
- 新反馈字段、操作描述、修复请求或最终消息中含注册私值时，在传输前拒绝；两臂 Provider 消息均没有宿主引用、原始覆盖键、工具结果或私有正文。
- 同源父三个不同的完整已执行无新增子代触发恰好随后十次选择机会的父冷却；仅当同一选中单元也独立累计三次才触发单元冷却，第 11 次各自可再选，新局部单元重置其已选父和单元计数。无新单元的不完整或超时子代、生成拒绝及已结算子代重放不得增加计数；轮到空索引时先试其他可用维度才根重启。
- 持久收据和原父 bundle 在中断恢复后重现同一选择与请求；缺 bundle 进入指定失败结算。配对报告仍分列 B/R/J、W/F/Q、`W/(W+F)`、`W/N_op`、真实调用/token/费用和失败。
