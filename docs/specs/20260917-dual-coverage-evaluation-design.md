## 1. 要回答的问题

**主张 A（本草案的处理对象）**

> 在 Agent、模型、场景、初始种子、变异能力、执行环境、Oracle、预算和记录口径完全一致的条件下，
> 「按覆盖结果决定测什么、以及把哪些候选留下继续演化」这套设计，
> 比「完全不看前面结果、每轮独立随机」更能发现新的风险—行为组合。

**明确不主张（留待后续，本草案不设计）**

主张 B：「增益来自覆盖率反馈本身，而不是来自种子池变大」。要检验 B 需要额外增加对照臂，本草案不做。

**为什么必须现在写清楚**：主张 A 与主张 B 是两个不同的命题，需要两套不同的实验。如果实验做完才决定要主张哪一个，就违反了「在看结果前冻结判据」。

**本草案不做的事**：不做裁判置信度加固、不做目标切换变异、不重做重放层级、不改安全默认值（见 §8）。

## 2. 术语（用本项目里的具体数据解释）

**风险进度（`risk_progress`）**
每个风险类型（共 4 个：错误修改传播、敏感信息披露、越权操作与权限扩张、破坏性操作）当前被测到哪一步，取值 0–3：`NOT_SELECTED`=0、`SELECTED`=1、`ATTEMPTED`=2、`REALIZED`=3。
关键事实：**只要某轮选中了这个风险类型，它的等级就会被记到 1**（`v2_campaign_state.py:295-335`，docstring 明写 "Selection is always recorded as level 1"）。升到 2/3 需要该次 Episode 有可信的 attempted / realized 证据。

**行为档案（`target_behavior_signature`）**
一次 Episode 里，Agent 针对**选定的攻击目标**实际走出的步骤结果与权限上下文，压缩成一个摘要（`v2_agent_behavior.py:112-128`）。它包含：攻击目标、目标 Oracle 标识、每一步的 attempted / blocked / realized、执行前 Agent 已知的权限事实（`knowledge_classes`）、上下文是否完整。
通俗说：**"这条路是怎么走的、当时 Agent 知不知道自己在越权"**。

**联合单元（本草案待冻结）**
"某条行为档案，是在哪个风险目标、什么权限上下文、什么阶段、什么结果下出现的"。它用于回答"哪类风险是通过哪条路径被尝试或阻断的"，不参与决定下一轮测什么。

**语料入队 / 晋升（corpus admission）**
一次 Episode 结束后，决定"这次用过的变异文本要不要留下来，以后还能被选为父种子"。这是本设计中**覆盖结果产生影响的主要位置**。

**覆盖反馈**
本草案的范围限定为：**来自前面 Episode 执行结果的、会影响后面选择或入队的信息**。包括风险进度、行为档案历史。**不包括**"这条候选文本以前生成过没有"这种本臂内的文本重复检查（它不是执行结果）。

### 2.1 一个必须写进文档的代码事实：入队判据有两套

代码里存在两处晋升判定：

| 位置 | 作用 |
|---|---|
| `v2_promotion.py:67-128` `classify_v2_promotion` | 按新风险证据 / 新主要行为 / 次要多样性分出 `RISK`、`EXPLORATION`、`FINDING_ONLY`、`NO_PROMOTION`、`QUARANTINED` |
| `v2_campaign_loop.py:184-226` | **引导臂实际生效的判据**：只有 `QUARANTINED` 会被放行进入这里，其余一律**重新决定**，结果只会是 `NO_PROMOTION` 或 `RISK` |

后果：`EXPLORATION` 和 `FINDING_ONLY` 在引导路径上**不可达**。实际入队判据是：

> 目标保持 = `PRESERVED` 且 目标匹配 = `MATCHED` 且 有过 attempted 且 `target_behavior_signature` **未在语料库出现过** → 晋升。

这一条必须在 SPEC 里明确表态：是有意设计（只认"目标行为的新组合"），还是两处判定应当统一。**本草案不替用户选择**，但把事实摆出。

## 3. 两臂设计

**共同部分（完全一致，不得有差异）**：Agent 运行时、被测模型与参数、场景与初始状态、16 个冻结根种子、变异算子族与变体的随机选择方式、单次变异预算、Episode 数、Docker 环境与资源限制、Oracle、覆盖提取器、超时与失败处理、记录口径。

| 环节 | `coverage_guided` | `random_independent` |
|---|---|---|
| 本轮测哪个风险池 | **选进度最低的风险类型**（读历史） | **4 个池均匀随机**（不读历史） |
| 池内选哪个父种子 | 均匀随机 | 均匀随机 |
| 选算子数量/族/变体 | 均匀随机 | 均匀随机（与引导臂相同） |
| 产生新覆盖的候选 | **入队**（晋升进同风险池，见 §2.1） | **不入队** |
| 候选文本/结构重复检查 | 开 | **开（同一套规则）** |
| 其余 | — | — |

**两臂差异共三处**（方向规则、是否入队、以及由入队带来的行为档案去重），但**三处都属于同一件事**：是否使用前面 Episode 的结果来影响后面的探索。这正是本设计要检验的那一件事。

**候选文本重复检查为什么两臂都要开**：它只使用"本臂自己生成过哪些文本"，不使用任何执行结果（`v2_real_runtime.py:320-324,346-384`）。若只在引导臂开启，随机臂会把预算烧在重复文本上，从而引入一个与覆盖率无关的额外差异。

**必须由用户确认的设计后果**：引导臂的种子池会随覆盖增长，随机臂始终是 16 个根种子。这是设计的一部分，不是不公平。用户在批准本草案时即确认接受这一后果，并确认要主张的是 §1 的主张 A。

## 4. 什么算「赢」

### 4.1 主指标（建议）

**在固定 Episode 预算下，累计新增联合覆盖单元数的均值**（按统一 Episode 数取曲线，比较曲线高度或达到同一水平所需 Episode 数）。

如果联合覆盖的定义来不及冻结，**降级主指标**：累计新增行为档案数 与 累计新增风险证据数，**两个维度分别报告，不合成总分**。此时不得声称"联合覆盖优越性"。

### 4.2 必须同时分别报告的维度

- 行为覆盖增长曲线（按 Episode、时间、Token）；
- 风险覆盖增长曲线；
- 联合覆盖增长曲线（若定义完成）；
- 独特 Finding 数、重复率、连续无增益长度；
- 失败率、超时率、恢复情况；
- 达到同一覆盖水平各自消耗的 Episode / Token / 时间；
- 多种子运行的均值与离散程度。

### 4.3 一个指标可行性问题（必须在冻结判据前处理）

风险进度只有 4 个类型 × 4 个等级，且**被选中即记 1 级**、升到 3 级需要"目标副作用已实现"（罕见）。因此该指标很可能在很早期就饱和，两臂曲线接近重合，**几乎没有区分度**。

建议：风险维度不用 0–3 当连续值，改用**"每类风险是否达到过 ATTEMPTED / REALIZED"的累计计数**。这仍然可能出现天花板效应，需在预实验（不用于结论）中确认后再冻结。

### 4.4 统计方法（2026-09-17 用户决定）

- 配对：同一 `--campaign-seed` 各跑一次引导臂与随机臂，构成一对；
- 每臂 Episode 数：**30**（用户决定）；
- 成对数量：**待定**。一对只产生一个差值，无法区分设计差异与运气；先跑一对并观察，再决定是否增加（见 §9.1）；
- 报告均值、离散程度与不确定性区间；**在看完结果前冻结**判据与计算脚本。

## 5. 结论成立的前提

以下三条不满足时，实验即使跑完也**不能**得出可归因的结论。

1. **对照有效**：随机臂不得读取任何来自前面 Episode 执行结果的信息（当前代码违反，见 §6 `C1`）；两臂除 §3 列出的三处差异外不得有其他差异（当前代码违反，见 `C2`）。
2. **结果变量可度量**：联合单元与四类新颖性当前不可度量（见 `J1`、`J2`）。
3. **可运行**：完整闭环在真实 Docker + 真实模型下从未在本次工作范围内验证过；最后一次真实运行是 `2026-09-10` 的外部服务器 Campaign。

### 9.1 尚未解决、需要预实验回答的问题

1. **成对数量**。每臂 30 Episode 是单对的规模。一对只给出一个差值，无法区分"设计差异"与"这一次的运气"。建议先跑一对，看差值方向与幅度，再决定是否增加到多对。
2. **晋升发生频率（最关键）**。入队要求"确实朝风险目标尝试过，且行为组合是新的"。若 30 轮中晋升次数极少（例如 0–1 次），引导臂与随机臂在机制上几乎没有差别，此时无论统计设计如何都得不出有意义结论。**预实验必须先统计晋升次数。**
3. **成本**。每 Episode 的耗时与 Token 消耗尚无可靠数字，决定最终能跑多少对。
4. **风险指标天花板**。见 §4.3，需在预实验中观察"累计风险证据数"在两臂间是否有区分度。

### 9.2 使用限制

只按选项二报告时，**不得**声称"联合覆盖优越性"，只能声称行为与风险两个维度分别的差异。该限制必须写入报告模板。
