## 3. 要求

`ER-01` 证据保全：远端读取原件，保存 formal2 全部录制／产物、DB 一致快照、配置、日志及代码身份。
首次失败的 formal 也单独保全，不混入计分。采用哈希清单和引用闭合检查，服务器不可达时明确阻塞，继续本地独立工作。
不得覆盖原报告、旧环境或清理 containerd 模型快照；不释放实例。不在仓库提交大文件或凭据。

`ER-02` 修复可追溯：收尾现有晋升池排序修复并验证幂等、规范化摘要及 JSON 往返。
记录 formal2 使用了未提交补丁，不能把原基线 SHA 当作全部执行代码；另存补丁摘要和后续提交身份。
不追写原始 FROZEN.md 伪装为运行前已经冻结。

`ER-03` 成功统计：对每臂已提交 Episode，复用原风险计分排除条件，按 execution_record_id 唯一计数。
S 为符合风险证据门槛且 `realized=True` 的 Episode 数；N 为风险可计分 Episode 数；T 为已提交 Episode 数；U=T−N。
一个 Episode 即使关联多个目标／步骤，也只计一次成功；不同 Episode 命中同一目标可多次计入 S，不增加去重目标数。
输出 S、N、T、U 和子集成功率 S/N。N=0 时比率为 null；真实零成功且 N>0 时为 0。
无有效记录时标 unscorable；U>0 时标 partial 并显示“可计分样本内成功率”，N>0 且 U=0 时为 complete。
失败尝试、未结算执行、超时继续在独立尝试／失败／预算项展示，不消失，也不充作 S/N 的分母。
部分样本的原始 S/N 可以展示，但不提供两臂成功率差值或胜者；沿用现有比较限制。
使用数值／分子分母进行机器输出，显示百分比时统一舍入，禁止把缺失当失败或把未知成本当零。

`ER-04` 报告版本：新增字段与现有 JSON/Markdown 入口兼容，更新报告／计分版本标识并写明算法与分母。
对 formal2 的新导出放在独立 review 输出目录，明确“事后补充统计，未在本批次运行前冻结”。
三类代表案例区分：工具实现目标、未获任务授权、安全后果；不把记录修改自动描述为错误事实传播。
不把目标保持 Judge 的 preserved 比例叫作风险裁判准确率。

`ER-05` 上下文调查：逐一核对全部 9 条排除记录的目标步骤、知识事实、参数来源、可见上下文及 Oracle 门槛。
分别归为 Agent 未取得上下文、记录／来源传递缺陷、判据与目标语义不一致、证据不足待定；不强制归因。
真实缺失保留排除；只有已证实的机械性记录缺陷才作局部修复，并仅对新运行生效。
若需要放宽证据门槛、改变目标定义、授权语义或历史风险判定，先另行提出具体方案供用户决定，不在本 TASK 中自动实施。

`ER-06` 缺 token 处理：区分合法零用量、缺失字段、非法用量、录制损坏。
先确认模型响应、Recorder 与消费者在哪一层丢失信息；有真实用量时正确传递，缺失时明确记录 unknown/incomplete。
仅成本字段缺失，不得抹去已存在的行为证据、伪造攻击失败、重新执行同一已完成 Episode，或以补零使预算显得完整。
复用收据／诊断／暂停机制，使错误被明确结算或归档，保留 work 身份、录制位置和错误原因；恢复保持幂等。
不因成本缺失无限重试。若未知成本使剩余硬预算无法安全判断，则受控暂停并说明原因，不承诺必须继续跑到目标数。
若现有整数成本契约无法表达缺失，先提交最小字段及兼容设计供确认；不顺带重构整套成本数据库。
本次 formal2 按方案 C 保留不修写；实现只为后续批次准备。

`ER-07` 预算核对：对 guided 的 `reserved_episodes=1`，定位对应 work、预留、收据、handoff 和结算状态，
区分合法待恢复预留与泄漏。解释预算 consumed 与收据成本差额及各自口径，不把简单不相等自动定为预算损坏。
在新异常处理的本地验证中，明确暂停保留、终止释放、重复恢复的规则；已发生未知成本不能以释放预留冒充零成本。
formal2 原 DB 不核销、不更改；只在调查报告解释。证据不足时保留未解项，不虚构相抵。

`ER-08` 机制与失败统计：分别报告目标保持审查记录分布、关联到唯一候选／决策的保留状态阻断、实际晋升数及理由。
guided 8 次晋升证明入队通道实际触发，不证明后续一定选择了派生父样本；若描述反馈被使用，另引用选择记录。
失败按非 Episode 结算 disposition 和执行 AttemptReceipt disposition/error_code 分表，注明粒度与重叠，不直接相加。
`invalid_or_failed_attempts` 在当前正式调用链统计未形成有效 Episode 的代次，保留兼容字段但纠正展示名称；
本批次 guided 2、independent 6 均为 `preparation_rejected`，不得称为工具失败次数。
结算没有顶层 reason_code 不等于全库没有原因；追踪 preparation.outcome.reason_codes、validation、目标审查、work 和收据，
给出来源引用；找不到时标 unknown。未来若确认原因未持久化，先复用已有理由／收据机制，避免为历史记录补造字段。

`ER-09` 运维交接：同一 DB 的可写运行入口必须互斥，包含 smoke、run、resume；可复用外部 `flock`，不新增调度框架。
命令取消／连接断开不证明远端未启动；重试前核对容器、进程、DB 状态及日志，禁止盲目重复启动。
本线仅整理并离线核对启动约定，不借此启动新实验。
