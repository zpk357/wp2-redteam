## 1. 目标与范围

解释一次工具调用前哪些信息实际进入了 Agent 的模型输入，以及这些信息怎样关联到参数来源和运行时可见性事实。
先尽力利用旧归档；只有确实缺失时，才为未来录制补最少的证据。主要覆盖 formal2 使用的 LangGraph Runtime。
不要求读懂模型内心，不将“输入中出现”自动当作“有权限”，也不将“来源未引用”自动当作“Agent 从未看过”。
不改变 Oracle、风险门槛、三条晋升规则或成功计数；不修写 formal2 原件，不启动模型、Docker 实验或第三批次。
不新增服务、可视化平台、通用模型网关或数据库体系。DeepSeek Harness 只需不受破坏，新增留证覆盖范围明确标注。

## 2. 已知线索与待证事实

formal2 有 9 条 context-incomplete。此前调查已定位到 required_resources_visible，归因尚未最终确定。
“只留了提示摘要、必然无法还原”仍需复核：

- `RecordedModelDecision` 有 before_checkpoint_id、input_digest；`CheckpointRecord` 可引用 state_artifact。
- `agent_image/app/replay/state_codec.py` 的状态白名单包含 messages、prompt；需检查**实际归档**是否含这些字段，而非凭代码认定已保存。
- `ReactDecisionRecorder` 的 input_digest 针对 React messages；Provider 可转换消息、追加收尾指令或格式错误重试提示。
- 实际参数来源通过 `OfficeV2Session._resolve_argument_sources` 与 `infer_exact_argument_sources` 生成，可能与“资源曾在输入中出现”不等价。

## 3. 要求

`VE-01` 旧证据优先：逐条从 execution/manifest → decision → checkpoint/state artifact → messages／工具返回／任务绑定还原。
标记为精确还原、部分还原或不可还原；只有规范化输入摘要吻合时，才声称还原了对应 Recorder 输入。
用当前模板猜测出的文本不能冒充历史原文；Provider 最终请求若无记录且无法证明转换版本，则保留未知。

`VE-02` 时间与来源：以 decision_index、调用序号和重试次序关联，区分资源首次展示、动作前输入、动作后的工具结果。
操作自身的成功返回不能反过来证明执行前已可见。任务文本之外，还要检查系统／workspace context、工具输出、可信冻结绑定。

> **执行注记（2026-09-20）**：用户确认"任务直接给出的资源参考值算作可见来源"（即可信冻结绑定）。
> 实现见 `7e2efa6`：绑定证据参与来源推断，引用形态覆盖资源引用映射与等于绑定资源／版本 id 的
> 标识字符串，生成与验证两端同口径；无对应绑定的引用与"展示但未引用"仍不算来源。
对资源 ID、版本、别名及字段结构做语义核对，不只用全 JSON 字符串搜索。

`VE-03` 最小新增证据：如果旧机制不能保证未来的输入可审计，复用 ArtifactStore/Manifest/录制出口，保存有序消息原文或可验证还原引用。
至少关联执行 ID、decision_index、Provider 请求序号、记录位置、消息角色／顺序、工具结果内容及实际提供的工具 schema（或其不可变引用）。
区分 Recorder 输入与 Provider 最后一次应用层请求；若两者不同，保存差异或最终请求及关联摘要。
格式错误重试的请求也需单独关联，不能只记最后成功返回。范围止于应用层传给模型客户端的请求，不声称等同服务端分词／实际注意到的内容。
复用现有 canonical digest 算法；不改变旧 input_digest 的含义。无信息差距时复用已有引用，不重复保存同样的大文本。

`VE-04` 兼容与失败：旧录制可继续读取，新证据缺失时显示 unavailable，不伪造原文，也不破坏已有严格重放。
仅证据传输或引用的机械缺陷可局部修复，不能通过补 visible=True 或改 Oracle 来让样例通过。
写入失败、缺件、摘要不匹配必须显式呈现；不以截断文本却保留完整标记掩盖缺失。
采用已有产物目录、权限与传输机制，不采集连接凭据／HTTP 授权头或环境变量；合成任务消息作为实验产物，不输出到普通控制台日志或 Git。

`VE-05` 验证：用现有本地模型替身及真实工具运行时，验证“输入展示 → 参数来源 → pre_action_knowledge → context_complete”。
覆盖已展示并正确引用、从未展示、展示但来源遗漏、仅调用后出现，以及 Provider 追加／重试输入。
若现有可见性判据将“展示但未引用”判为不可见，先保留该结果并指出差异；不在本规格内放宽标准。

`VE-06` 交付结论：9 条记录分别给出原件引用、展示情况、来源情况、判据结果与归因边界；不能一概归为 Agent 猜 ID 或记录丢失。
历史证据确实缺失可以保持待定，但应验证未来同类情况已有足够证据。完成任务不要求修改任何历史评分。
为下一轮交接输入证据检查方法和新源码／镜像需求；运行条件仍可人工核对，不引入自动判优门槛。

## 4. 验收

- `VE-AC-01`：9 条旧记录逐条完成 checkpoint/message 原件调查，至少一个完整对照；可还原结论由摘要或明确的引用链支持。
- `VE-AC-02`：本地样例中输入证据从真实录制出口落盘后可读取，能定位到工具调用前的正确 decision；未来记录缺件可检测。
- `VE-AC-03`：已展示／未展示／来源遗漏／事后出现四种情况可区分，无“动作后证据证明动作前可见”。
- `VE-AC-04`：Provider 的正常调用和一次追加／重试请求均可审计；旧录制与严格重放兼容测试通过。
- `VE-AC-05`：历史原件哈希不变，没有真实模型调用、搜索策略／风险判据变化；未解释案例如实保留。
