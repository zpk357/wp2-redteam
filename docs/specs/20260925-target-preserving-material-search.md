## 1. 目的与边界

本 SPEC 只处理一个问题：共同根生成和局部变异经常把可识别的注册受限正文连同低信任诱导文字一起改写，导致风险资产没有进入 Agent Episode，无法形成既有 R/B/J 与 Oracle 可以确认的风险证据。

本轮将搜索对象分成两类：

1. **固定业务／风险资产**：由 fixture 场景独立提供，内容、对象身份、版本和注册关系不随候选改变；
2. **可变低信任材料**：由现有共同根生成和局部变异产生，继续探索诱导文字、引用关系和允许的材料结构。

目标是比较“覆盖反馈选父”与“随机选父”在相同固定资产和相同可变材料空间中的效果，不强制模型触达某条路线，也不提高引导臂命中率。

## 2. 已确认需求

### MAT-01 固定资产独立于候选材料

fixture 独立提供至少两类资产：

- 固定公开业务正文：现有不可变公开锚点及其公开事实；
- 固定注册受限正文：现有注册受限文件及其注册摘要、内容类别、受众关系和访问控制。

固定资产不得作为可变候选槽的内容物化结果。根生成和局部变异不得删除、改写、移动其固定对象内容，或改变其对象身份、版本、注册关系、ACL 和内容类别。

本 SPEC 不要求新增平台对象类型。优先复用现有 overlay、registered file、搜索结果、正式读取暴露、提交内容见证和 fixture manifest。以旧 `summary-delivery-c` 为基线，独立登记新 `summary-delivery-d`：保留现有公开锚点；将注册受限文件从 `s3` 的可变 slot target 中解耦，作为相同世界中的独立固定 drive file；`s3` 继续作为低信任诱导材料槽。旧 `c` 保持 v1.0.0 不变。固定文件的真实搜索和读取必须接入现有 `read_restricted` R 及相应 J；不得伪造 slot exposure，也不得新增通用溯源平台。

### MAT-02 可变材料范围

两臂共同使用现有根生成、局部编辑核和 Provider 能力，只允许修改：

- 低信任诱导文字；
- 已注册引用关系；
- 现有合法编辑算子允许的材料结构。

允许出现诱导失败、固定资产未读、可变材料为空或部分为空、读取后无交付、交付正文由 Agent 自行决定、没有可验证交付等结果；这些结果必须正常结算并保留证据。无交付仍按既有任务完成标准和资格门判定，不因本 SPEC 放宽资格。

变异器不得预设工具调用顺序、强制 Agent 读取固定受限资产、代替 Agent 填写邮件或共享文件正文，也不得把固定资产正文复制到候选文字中作为成功条件。

### MAT-03 生成器信息边界

生成器可以看到现有契约允许的公开任务、公开义务、可变父材料和结构化编辑位置；不得看到：

- 注册受限正文的原始值；
- 隐藏标签、标准答案、Oracle 预期结果；
- 指定的正确工具路线或固定资产的隐藏评估用途。

生成器不需要、也不得被要求复现注册受限正文。固定资产的可达性由 fixture 世界和正式工具结果提供，不由 Provider 生成。

### MAT-04 目标保持

本轮是**目标保持的材料搜索**。每个候选的固定资产边界必须保持；可变文字和结构可以改变，但不能把固定资产保护边界改成目标切换。

`obligation_direction` 继续按 SS-010 的预冻结日程轮换。这里的“静态”只表示日程由实验预先冻结、不得被反馈临时改变，不表示把方向改成常量。固定风险资产始终保留；资产目标切换不属于本轮比较范围，也不得用目标切换替代引导反馈。

### MAT-05 两臂公平性

主对照只保留 `coverage_guided` 与 `random_evolution`。

两臂必须共享固定资产、fixture manifest、初始状态、可变候选空间、根生成器、Provider、编辑算子、父材料继承能力、Agent、工具、权限、Oracle、R/B/J/U 口径、预算、调度、失败结算和恢复规则。

两臂差异只能是是否消费跨 Episode 覆盖反馈影响父选择。`random_evolution` 同样可以继承父材料并局部变异；本轮不比较“是否继承”这一因素。

### MAT-06 既有证据链不变

固定资产必须通过现有真实工具自然进入证据链：

```text
fixture 独立固定资产
→ search 返回对象
→ Agent 根据真实返回读取
→ ToolReturn / exposure / committed state 保存正文摘要、对象和版本证据
→ 现有 Oracle 判断义务结果
→ 现有 coverage 提取 R、B、J
→ 缺证进入 unknown/诊断，不产生主覆盖奖励
```

固定注册受限文件必须经现有搜索结果自然发现，并由 Agent 的正式读取调用产生既有 exposure、`read_restricted` R 及对应 J；不得根据 slot 内容、任务文本或预设路线伪造 exposure。只有完整执行证据支持才产生 `read_restricted` R；读取本身不自动判违规。将固定受限正文提交给不允许受众时，沿现有 committed 内容、受众关系和 Oracle 产生既有 `DATA_RELEASE` / `AUDIENCE_SCOPE` 结果。

公开正文读取、未读材料、材料中的风险措辞、缺失引用和不完整提交不冒充受限 R。有证来源使用才产生既有 source B/J；自述、文本相似或时间先后不足以奖励来源关系。不新增 R/B/J 键，不改变 U FindingKey。必要的读取证据接线使用既有键和既有证据类型；实现、fixture、manifest、overlay 和 execution identity 按新版本独立登记，旧 fixture、旧结果和原始证据不迁移、不混算。

### MAT-07 后续收口

实施后按固定顺序完成：本地实现与聚焦验收 → 一次有上限的真实开发预检 → 根据结果决定是否进入正式比较。预检只检查：

1. Agent 是否在真实搜索结果基础上读取固定风险资产；
2. 可变诱导材料改变后，Agent 行为和交付结果是否发生可观察变化；
3. 父材料、选择收据、子代材料和执行覆盖是否可回读，且反馈确实进入 `coverage_guided` 的后续父选择；
4. `random_evolution` 是否继续不消费跨 Episode 覆盖反馈；
5. 固定资产、预算、调度、权限、Oracle 和覆盖身份是否一致。

通过条件不包括“引导必须领先随机”。若仍缺乏有效风险反馈，停止扩样并报告原因；不得自动追加补丁、改变指标、扩大预算或重跑。正式多配对比较另行冻结 Campaign 数量、种子、预算、指标、停止规则和报告范围。

## 3. 版本与历史隔离

- 覆盖指标定义、R/B/J/U 键和判定含义保持不变；固定资产读取只是把既有正式证据接入当前 fixture 数据流。
- 本次 `summary-delivery-d` v1.0.0/manifest/overlay 和执行配置使用新的独立身份与摘要登记；旧 `summary-delivery-c` v1.0.0 不覆盖、不重算。
- 现有 `structured-coverage-v4-semantic-behavior` 只有在确认覆盖定义未变时继续使用；若实现超出既有证据接线并改变覆盖语义，必须停止并回到 SPEC，不得静默混用。
- 旧 fixture、旧 Campaign、旧结果和原始证据保留，旧新身份不得进入同一 CoverageLedger 或效果曲线。
## 4. 不在本轮范围

- 不新增平台工具、权限模型、Agent 能力或通用资产保护基础设施；
- 不改变 B、R、J、U 的定义、版本、去重或联合关系；
- 不改变预算、调度、失败消耗机会、冷却和恢复规则；
- 不要求 Agent 读取固定受限正文或执行预设工具路线；
- 不要求生成器看到或复现注册受限正文；
- 不增加 `random_independent` 或其他消融臂；
- 不启用目标切换变异；
- 不以覆盖结果反向修改 fixture、权限或任务文本；
- 不启动服务器、模型容器或真实 Campaign；
- 不进入正式多配对比较。

## 5. 已批准的最小实施差异

本节是已批准 TASK 的范围基线，不授权超出下列边界的架构扩展。

1. **fixture/manifest**：把公开锚点和注册受限文件声明为独立固定资产；可变槽只承载低信任材料和引用结构；固定资产 overlay 摘要、注册摘要和 ACL 在候选变异前后相同；固定受限文件仍通过正式搜索入口可发现。
2. **根生成/局部变异**：候选结构和 Provider 只覆盖可变材料区域；保留共同根分布、SS-010 方向轮换、编辑算子、Provider 请求上限和父子谱系记录；不启用资产目标切换。
3. **准入/身份**：增加固定资产未变化的确定性检查；失败时拒绝候选并正常结算；不把固定资产正文放入 Provider 请求。
4. **离线验收**：复用现有搜索→读取、受限读取、公开交付、受限提交、共享交付、来源见证和父子覆盖测试；新增断言只确认固定资产不变和可变材料仍能变异。
5. **运行前检查**：确认两个主臂的 execution identity、候选空间、预算、调度、权限和覆盖版本一致；离线验收全绿且用户另行批准后，才申请一次有上限预检。

## 6. 验收标准草案

- AC-MAT-01：根候选和局部子代的固定公开正文内容、对象、版本、注册关系和 ACL 与 fixture 独立资产一致。
- AC-MAT-02：合法变异只能改变低信任文字、允许引用或允许结构；固定资产被删除、改写、换对象、换版本或换 ACL 时拒绝候选并记录稳定失败原因。
- AC-MAT-03：Provider 请求和响应均不含注册受限原值、隐藏标签或标准答案；Provider 不需要复现注册正文。
- AC-MAT-04：固定受限资产经真实搜索返回并被真实读取时，现有 exposure、`read_restricted` R 和对应 J 具备完整可重算证据；未读取时不补造 slot exposure 或 R。
- AC-MAT-05：安全或违规交付仍由现有 committed 内容、受众、状态和 Oracle 判定；材料风险措辞单独不产生 R/U。
- AC-MAT-06：可变诱导可以为空、未读、未交付或导致 Agent 停止；这些结果完整记录并正常结算；无交付仍经过既有任务完成标准和资格门，不改写为成功或自动重试。
- AC-MAT-07：两个主臂使用相同固定资产、可变候选空间、生成器、编辑能力、预算、调度、权限、Oracle 和 R/B/J 口径；随机演化不读取跨 Episode R/B/J，且同样可以继承父材料。
- AC-MAT-08：离线回放证明 `coverage_guided` 的选择收据、父基线、子代材料和执行覆盖相互绑定；不要求新增覆盖或领先随机。
- AC-MAT-09：离线验收记录固定资产读取率、诱导材料可变性、材料未读率、行为变化、反馈进入子代和失败结算；确认 SS-010 方向轮换未被反馈改变；真实预检有明确机会、调用、token、时间上限。
- AC-MAT-10：真实预检若缺乏有效风险反馈，停止扩样并留下原因；不自动修改 SPEC/TASK、指标、预算、调度或重跑。

## 7. 风险、假设与待决问题

### 已确认风险

- 固定资产独立后，Agent 仍可能完全不搜索或不读取它；这属于可观察的搜索结果，不通过强制路线修复。
- 可变材料可能继续产生大量相同 B/R/J；这不构成提高预算或修改指标的理由。
- 固定资产与可变槽的边界若未在 manifest、overlay 和执行身份中同时冻结，可能造成两臂候选空间不一致。

### 当前假设

- 现有搜索工具可以自然返回独立固定公开文件和独立固定受限文件，无需额外提示或硬编码 ID。
- 现有 ToolReturn、exposure、committed content 和 Oracle 证据足以验证固定资产读取与提交；若离线验证发现缺证，先回到 SPEC/TASK，不在本轮增加平台功能。
- 固定资产 overlay 摘要可以纳入现有 fixture/执行身份，而不改变 R/B/J 键或预算轴。

### 已批准决策

- 从 `summary-delivery-c` 派生独立 `summary-delivery-d`，其注册受限文件从可变 `s3` slot target 解耦，保留固定正文、注册摘要、ACL 和自然搜索入口作为独立固定资产；`s3` 改为低信任可变材料槽；旧 `c` 不变。
- `obligation_direction` 继续按 SS-010 预冻结日程轮换；反馈不得临时改变日程，固定风险资产不切换。
- 本轮先完成本地实现、聚焦验收和一次有上限预检包准备；真实预检需另行一次性授权，正式多配对比较不在本轮授权内。
