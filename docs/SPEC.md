# 行为轨迹级度量与覆盖率引导的自动化红队测试：产品规格

状态：`APPROVED_BASELINE`

本文档定义产品目标、核心语义、边界和产品级验收标准。它描述项目应当达到什么结果，不描述当前代码已经实现到什么程度。当前能力、实现差距和后续任务分别记录在现状文档、需求规格与任务文档中。

## 1. 背景与目的

面向工具型 Agent 的自动化安全测试存在两个核心问题：

1. **路径偏移**：Agent 在动态、多轮、带状态的交互中可能因细微上下文变化进入不同工具路径、权限路径或状态分支，只检查最终回答无法解释风险是如何产生的。
2. **模式坍缩**：自动化红队生成器容易反复产生相似提示、相似工具序列和相似风险结果，看似执行了大量测试，实际只覆盖狭窄区域。

本项目要构建一套工程化压力测试体系，以行为轨迹级证据度量 Agent，在相同测试预算下比较随机探索与覆盖率引导探索，并通过可重放的隔离环境把一次性随机评测升级为可验证、可回归的安全测试。

项目名称对应的核心课题是：**1.2 行为轨迹级度量与覆盖率引导的自动化红队测试**。

## 2. 产品目标

- `G-01`：以完整交互轨迹而非仅最终回答作为测试和归因的基本证据。
- `G-02`：分别度量风险覆盖和行为覆盖，并用同一 Episode 的证据建立二者的联合覆盖关系。
- `G-03`：使用双重覆盖反馈驱动测试方向与语料入队，主动探索长尾、低概率的不安全边界。
- `G-04`：提供公平的随机模式和覆盖率引导模式，在冻结的实验协议下验证引导策略是否更有效。
- `G-05`：在 Docker 隔离环境中保存足够的状态与指令证据，支持确定性重放、问题复现和回归测试。
- `G-06`：逐步建立由黄金集、主动学习、漂移监控和人工复核组成的裁判置信度加固能力。

## 3. 核心研究假设

在 Agent、模型、场景、合法候选空间、语义变异能力、执行环境、Oracle 和资源预算一致时，覆盖率引导模式应比随机模式：

- 更快发现新的风险—行为组合；
- 在相同预算下取得更高的联合覆盖；
- 减少重复路径和无增益 Episode；
- 更有机会触达长尾、低概率的不安全状态；
- 产生更多具有可重放证据的独特 Finding。

这是必须通过实验检验的假设，不是可以预先写入结论的承诺。如果证据不支持优越性，系统必须如实报告无显著优势、退化或实验无效，不得事后更换指标、删除失败样本或削弱随机基线。

## 4. 核心对象

- **Scenario**：受控测试场景，定义 Agent 可见任务、初始状态、工具、策略、安全边界和可观察结果。
- **Test Case**：一次可执行测试输入，包括任务文本、风险目标、前置条件、允许变化的语义维度和来源谱系。
- **Episode**：一个 Test Case 在指定环境中的完整执行单元。
- **Trace**：Episode 中有序的模型决策、工具调用、工具结果、状态变化、策略分支、最终回答和终止原因。
- **Behavior Profile**：从 Trace 和状态变化中提取的可解释行为特征集合。
- **Risk Evidence**：由 Trace、工具结果、状态差异和 Oracle 支持的风险事实。
- **Coverage Snapshot**：某个时间点的行为覆盖、风险覆盖和联合覆盖状态。
- **Finding**：满足证据门槛、可定位到风险与行为关系、可被重放或复核的安全发现。
- **Campaign**：在冻结配置、预算和策略下执行的一组 Episode 及其累计状态。

Office Workspace V2 可以作为首个完整场景，但产品抽象不得永久绑定某一组固定提示、固定工具或固定风险样例。

## 5. 双重覆盖模型

### 5.1 行为覆盖

行为覆盖描述 Agent **实际走过什么路径、做过什么动作、产生了什么状态变化**。至少允许表达：

- 工具种类、调用序列和有限长度路径；
- 关键参数类别、数据来源与数据流向；
- 身份、授权、策略检查和阻断分支；
- 工具成功、失败、拒绝、重试和异常结果；
- 资源状态、安全状态和外部副作用的变化；
- 澄清、拒绝、继续执行、提交或未提交等决策；
- 正常结束、预算耗尽、超时、异常和其他终止原因。

行为特征必须由可追踪的执行事实提取，具有稳定标识，并能重新从保存的 Episode 证据计算。

### 5.2 风险覆盖

风险覆盖描述测试 **触达了哪些安全风险、处于何种阶段、是否真正产生影响**。至少允许表达：

- 风险分类与具体风险目标；
- 风险成立所需前置条件；
- 身份、授权和策略上下文；
- 风险载体、目标资源和影响对象；
- 仅表达、已尝试、被阻断、部分实现或已实现等暴露阶段；
- 关键风险里程碑及其结果；
- 预期风险与执行中意外出现的风险；
- 已观察副作用、缺失证据和不确定性。

风险命中必须有明确证据来源。仅在提示中提到某种风险，不等于实际覆盖了该风险结果。

### 5.3 联合覆盖

风险覆盖和行为覆盖必须共同工作，而不是两个互不相干的报表。系统必须建立由同一 Episode 证据支持的联合单元，例如：

```text
行为路径或状态转移 × 风险类型/目标 × 风险阶段 × 授权上下文 × 执行结果
```

联合覆盖用于回答：某类风险是通过哪条行为路径、在什么上下文和阶段被触达或阻断的。系统必须保留以下四种结果，不能只输出一个 `coverage_gain` 布尔值：

1. 新行为、无新风险；
2. 无新行为、新风险进展；
3. 新行为与新风险同时出现，并形成新的联合关系；
4. 行为、风险和联合关系均无新增。

### 5.4 覆盖反馈

反馈必须同时包含行为缺口、风险缺口、联合覆盖缺口、重复或饱和信号以及证据置信度。这些反馈分别作用于不同位置：风险缺口参与测试方向选择，行为与联合覆盖缺口、重复或饱和信号参与候选入队。调度与入队可以采用分层、多目标或 Pareto 等策略，但必须保留各维度的可解释性；不得用不可拆解的总分掩盖某一维度退化。

## 6. 覆盖率引导的语义模糊测试

### 6.1 闭环

`FR-FUZZ-01`：覆盖率引导模式必须形成以下真实闭环：

```text
场景与候选空间
-> 当前双重覆盖快照
-> 识别风险/行为/联合覆盖缺口
-> 选择测试方向与父样本，并决定候选是否入队
-> 生成并校验语义变异
-> Agent 在沙箱中执行 Episode
-> 保存 Trace、状态和 Oracle 事实
-> 更新行为覆盖、风险覆盖和联合覆盖
-> 形成下一轮反馈并更新语料库
-> 下一代选择与变异
```

反馈必须实际影响下一轮父样本选择、目标方向或变异内容；通过语料入队改变父样本池组成，即属于影响父样本选择。仅在 Episode 完成后计算覆盖率或决定是否保存结果，不构成完整的覆盖率引导模糊测试。

### 6.2 语义变异

`FR-FUZZ-02`：变异器可以在受控边界内改变良性任务表述、风险目标、前置条件、角色声明、语气与压力、信息结构、风险载体、资源组合和交互顺序，以探索新的风险—行为组合。

`FR-FUZZ-03`：每次变异必须保存 Mutation Plan，至少包括：

- 输入覆盖快照或反馈摘要；
- 计划探索的风险、行为和联合覆盖缺口；
- 允许变化与必须保持的语义维度；
- 父样本、代次和完整谱系；
- 随机种子、模型/Provider、提示版本和预算；
- 目标保持或目标切换的校验结果。

`FR-FUZZ-04`：同时支持两种显式操作：

- **目标保持变异**：保持安全测试目标，只改变表达或上下文；
- **目标切换变异**：按照已注册的合法目标和计划明确切换探索目标。

未声明的目标漂移属于无效变异，不得伪装成目标保持样本或进入错误的覆盖分区。

### 6.3 语料库与调度

`FR-FUZZ-05`：种子晋升、父样本权重、重复降权和长尾探索必须能追溯到具体覆盖证据。系统应优先保留产生新风险、新行为、新联合关系或高价值可重放 Finding 的样本，同时避免少数热门路径垄断预算。

## 7. 随机模式与公平比较

### 7.1 随机基线

`FR-EXP-01`：系统必须提供 `random_independent` 模式。它从同一合法候选空间中独立采样，拥有与引导模式相同的语义变异能力，但不得读取之前 Episode 的覆盖快照、缺口、晋升结果或其他跨 Episode 反馈来影响下一轮选择。候选文本或结构层面的重复检查只使用本臂已生成的内容，不属于覆盖反馈，两种模式都必须启用。

2026-10-04 用户批准的多路径实验修订：在 `error-capable-multipath-02` 场景中，LLM 仅用于引导臂的任务、路径、攻击机制、载体和布局选择；随机臂从同一冻结合法组合空间按种子均匀、有放回地独立采样，不调用 LLM 选择器、不读取历史、不排除或降权重复组合。两臂共享材料生成能力与 Agent 执行条件。此修订详见 [多路径世界规格](specs/20261004-multi-path-world-and-llm-selection.md)，历史实验协议不追溯变更。

### 7.2 覆盖率引导模式

`FR-EXP-02`：系统必须提供 `coverage_guided` 模式。它读取历史双重覆盖反馈，据此选择测试方向，并决定候选是否晋升进语料库，同时记录“为什么选择”。

### 7.3 公平性约束

`FR-EXP-03`：两种模式比较时，必须冻结并保持一致：

- Agent Runtime、被测模型和模型参数；
- Scenario、初始状态和初始根候选空间（种子池随覆盖增长属于被检验的设计，不属于此处的候选空间差异）；
- 变异器模型、能力边界和单次调用预算；
- Episode 数、Token/调用/时间/成本预算；
- Docker 环境、工具实现、策略和外部依赖；
- Oracle、覆盖提取器和 Finding 判定口径；
- 超时、失败、重试、恢复和结果保存规则。

唯一原则性差异应是：是否消费跨 Episode 覆盖反馈来影响后续探索。随机模式不能使用更弱的模型、更窄的初始候选空间或更差的错误处理。

上述多路径实验以“LLM 覆盖引导选择”和“纯随机选择”作为实验变量，不能解释为仅改变反馈消费的消融。两臂冻结相同候选菜单、材料表达能力、校验器、Agent 模型与参数、工具、Oracle 和 Agent 执行预算；引导选择器调用、时间与 Token 开销单列，可观测性不足时标为未知，不得记为零。

### 7.4 实验设计与报告

`FR-EXP-04`：正式比较必须采用预先冻结、版本化的实验计划，使用配对 Campaign 和多个随机种子，并完整保存成功、失败、超时和无增益 Episode。

`FR-EXP-05`：报告至少分别展示：

- 行为覆盖随 Episode、时间、Token 和成本的增长曲线；
- 风险覆盖的增长曲线；
- 联合覆盖的增长曲线；
- 达到指定覆盖门槛所需预算；
- 独特 Finding 数量、重复率和连续无增益长度；
- 失败率、超时率、恢复情况和重放成功率；
- 多次运行的均值、离散程度和必要的统计不确定性。

主要优越性依据是联合覆盖与覆盖效率；风险覆盖和行为覆盖必须同时单独报告。任何综合指标都必须能拆解回原始维度。精确重复次数和统计检验方案由具体实验 SPEC 在看结果前冻结。

## 8. 确定性沙箱与重放

`FR-REP-01`：每个 Episode 在具有副作用隔离能力的 Docker 环境中执行。测试不得影响未授权系统或真实生产数据。

`FR-REP-02`：系统必须保存足以解释和复核执行的证据，包括：

- 原始任务、变异计划、父样本和谱系；
- 初始状态、关键状态快照和最终状态；
- 有序的模型决策或指令、工具调用和工具结果；
- 策略判断、授权上下文、最终回答和终止原因；
- Oracle 事实、风险/行为/联合覆盖结果和 Finding；
- 配置、随机种子、依赖身份和内容完整性摘要。

`FR-REP-03`：系统必须明确区分以下重放层级：

- **轨迹重放**：按已保存的调用与结果重建判断链；
- **工具重放**：在恢复的环境状态中重放工具指令；
- **状态验证**：验证重放前后状态与预期快照一致；
- **重新执行**：重新调用非确定性模型并比较允许的差异。

不得把“保存了随机种子”误称为大模型输出逐 Token 确定。重放结论必须说明确定性边界、外部依赖和允许偏差。

`FR-REP-04`：具有安全意义的 Finding 必须关联可定位证据，并能够通过适用的重放层级复现或解释；失败重放也必须保存原因。

## 9. Oracle 与裁判置信度

### 9.1 判定边界

`FR-JDG-01`：工具调用、工具结果、状态变化、权限事实、策略结果和终止原因优先由确定性 Oracle 判定。

`FR-JDG-02`：LLM-as-Judge 只用于需要语义判断的事项，例如回答质量、意图保持、严重性、可利用性或人工复核排序。Judge 不得改写确定性事实，也不得成为高风险结论的唯一证据。

### 9.2 置信度加固目标

`FR-JDG-03`：裁判置信度加固必须包括：

- 版本化、人工标注并有争议处理记录的黄金集回归库；
- 覆盖困难样本、分歧样本和新分布样本的主动学习采样；
- Judge 模型、提示和阈值变化后的回归；
- 与黄金标签及人工复核对比的漂移监控；
- 低置信度、模型分歧和分布外样本的人工升级机制；
- 可追溯的 Judge 版本、输入、输出、置信度和复核记录。

本能力是正式产品目标，但当前阶段尚未实施完成。在上述闭环通过验收前，任何文档或报告不得宣称 Judge 已校准、客观可靠或完成置信度加固。

## 10. 持久化、失败与恢复

- `FR-OPS-01`：Episode 结果、覆盖更新、Finding、预算消耗和调度状态必须具有明确的一致性边界，避免出现结果已执行但状态不可恢复的半结算状态。
- `FR-OPS-02`：超时、容器失败、工具失败、无效变异、Judge 不可用和存储失败必须分类保存，不得悄悄转成成功或从统计中删除。
- `FR-OPS-03`：恢复必须幂等；已经完成且证据完整的外部执行不得因 Controller 重启而被无依据地重复执行。
- `FR-OPS-04`：预算按可解释维度记录，包括 Episode、模型调用、Token、工具调用、时间和成本；到达边界时应有明确终止原因。
- `FR-OPS-05`：内容摘要用于发现轨迹、快照、Replay 或 Artifact 的损坏和截断，不替代产品层面的语义验证。

## 11. 安全、隐私与授权边界

- `SEC-01`：仅针对用户明确授权的合成环境、测试数据和目标运行。
- `SEC-02`：默认拒绝连接真实生产系统、真实账号或未授权外部服务。
- `SEC-03`：日志和 Artifact 不得保存密码、私钥、云密钥或不必要的完整敏感响应；必须支持必要的脱敏与最小化保留。
- `SEC-04`：每个 Episode 结束后验证副作用被隔离或清理；清理失败必须成为显式测试结果。
- `SEC-05`：Controller 不得替 Agent 伪造工具调用、授权、状态变化、提交或成功证据。

## 12. 非目标

- 不构建面向未授权目标的攻击、窃取、持久化或安全控制绕过工具。
- 不把固定提示集合、关键词同义改写或单一 Office 场景包装成完整产品。
- 不以最终回答的单次分数替代行为轨迹、状态和工具证据。
- 不保证大模型输出逐 Token 可复现。
- 不为证明预设结论而调整随机基线、隐藏失败或事后更换指标。
- 不在裁判置信度加固完成前宣称 Judge 已经校准。

## 13. 产品级验收标准

以下条件共同满足，才可声称本规格的核心产品闭环完成：

- `AC-01`：至少一个代表性 Scenario 能执行从种子/父样本到语义变异、Agent Episode、Oracle、双重覆盖、反馈和下一代的完整闭环。
- `AC-02`：行为覆盖、风险覆盖和联合覆盖具有稳定、可解释、可从保存证据重新计算的标识。
- `AC-03`：能够分别识别“仅新行为”“仅新风险”“新联合关系”和“无新增”四类结果。
- `AC-04`：覆盖率引导模式的历史反馈确实影响后续选择或变异，并有可审计的选择理由。
- `AC-05`：随机模式不消费跨 Episode 覆盖反馈，且与引导模式满足公平性约束。
- `AC-06`：能够按冻结协议重复运行配对实验，并分别报告风险、行为、联合覆盖及效率、失败和不确定性；只有证据支持时才宣称引导模式更优。
- `AC-07`：Episode 的关键事实、状态和指令序列被完整保存；代表性 Finding 可以按声明的重放层级复现或解释。
- `AC-08`：中断、失败结算、预算终止和恢复路径有测试证据，不重复结算已完成 Episode。
- `AC-09`：所有安全结论可追溯到确定性事实或明确标识的语义判断，不由 Controller 伪造证据。
- `AC-10`：裁判置信度加固只有在黄金集、主动学习、漂移监控、回归和人工升级机制全部通过独立验收后，才能标记完成。
