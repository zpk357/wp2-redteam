## 1. 目标

实现一个有限的新 fixture 和两阶段 Agent 会话，使材料变异能够影响固定分支的可达性，且读取之后有可观察的行动阶段。比较条件仍是覆盖反馈选父与随机选父，不能把控制器改成路线脚本。

## 2. 范围

### 包含

1. 新建 `summary-delivery-e`，独立登记公开索引和固定资产集合，并登记六个可表达机会映射；固定资产不进入候选材料。
2. 保留低信任诱导槽、共同 Provider、合法编辑算子、父子谱系和现有准入规则。
3. 增加本实验限定的同一 Episode 调查阶段和行动阶段编排，保存阶段边界及可关联的决策/事务证据；不建设通用两阶段平台。
4. 复用现有正式工具、ToolReturn、exposure、committed content、Oracle 和 R/B/J/U 提取。
5. 为两臂使用同一阶段协议和资源限制，保持 `random_evolution` 的反馈隔离。
6. 编写运行前离线验收和一次最终运行包草案；不执行运行。

### 不包含

- 不修改旧 fixture、旧 Campaign、旧原始证据或旧覆盖结果；
- 不修改 B/R/J/U 定义、FindingKey、权限模型或资格门；
- 不强制 Agent 选择固定资产、预设工具顺序或填写交付正文；
- 不增加 `random_independent`、额外消融臂或通用资产保护平台；
- 不自动提高预算、补偿失败机会或在失败后创建下一版方案；
- 不启动服务器、模型、Docker 或真实 Campaign。

## 3. 预计修改区域和数据流

- `fixtures/summary_delivery_e.py`：固定资产、公开索引、分支映射和新 manifest/overlay 身份；
- fixture/manifest/overlay 类型：固定对象的正文、版本、ACL、注册关系和执行身份摘要；
- envelope/session/runtime：两阶段任务消息、阶段预算、同一世界状态、决策/事务关联和结束原因；两阶段都使用同一工具目录与权限，调查阶段任务要求至少尝试一次公开索引来源和一次注册受限来源读取；
- bundle/checkpoint/replay：持久化 `phase_id`、阶段转换事件及 action request/transaction 关联，不把阶段元数据伪装成 B/R/J；
- exposure/coverage：固定文件真实读取仍生成既有受限 R、读取权限 B 和 same-exchange J；阶段边界不得伪造曝光；
- campaign/search：父材料、选择收据、冻结基线、子代执行和失败结算继续沿用；两臂只在反馈消费上不同；
- tests and reports：离线分支矩阵、阶段窗口、公平性、恢复和历史隔离证据。

## 4. 实施顺序（仅在 TASK 获批后）

1. 只读审计现有 envelope/session/runtime 的单阶段假设，确定最小两阶段接入点；若需要改变 B/R/J、权限或通用平台，停止回到 SPEC。
2. 建立 `summary-delivery-e` fixture、固定资产集合和六个机会映射，生成独立 manifest/overlay/freeze identity；验证旧 c/d 资产摘要不变。
3. 接入本实验限定的两阶段会话：固定调查任务与固定行动跟进消息；调查阶段最多 8 次决策并预留行动阶段最多 8 次决策。调查阶段正常/提前停止且仍有预留预算与墙钟时只发送一次行动阶段续接消息；硬预算或硬超时则直接终态；阶段预算、状态连续性、停止和失败结算写入证据。
4. 保持可变材料只修改低信任诱导内容和合法结构；验证 Provider 不见固定受限正文；两臂候选摘要一致。
5. 复用和补齐固定资产 search→read 的正式 R/B/J 证据；不从 fixture ID、slot 内容或脚本补造 exposure。
6. 编写脚本化 Agent 的六分支离线回放和失败/恢复测试；验证读取后的行动阶段决策关联。
7. 编写 guided/random 公平性和反馈隔离测试；验证同一候选空间与相同两阶段预算。
8. 编写一次最终 Campaign 运行包，冻结身份、预算、主指标、有效性条件和收口规则；本 TASK 仍不得授权运行。
