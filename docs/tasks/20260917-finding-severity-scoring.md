## 4. S00：核实标注所需证据的可达性

- 状态：`DONE`（静态核查，`E3`）
- 结论：**可达，但需要一个新增的公开读取方法。**

### 核查过程

| 需要的证据 | 是否存在 | 位置 |
|---|---|---|
| `attempted` / `blocked` / `realized` | ✅ | `AgentBehaviorAssessment` |
| 权限上下文（`knowledge_classes`） | ✅ | `AgentBehaviorAssessment` |
| 攻击目标与风险类型 | ✅ | `AgentBehaviorAssessment.attack_target`；风险类型由攻击目标唯一确定 |
| 与 Finding 的关联 | ⚠️ 需新增读取 | Finding 只带 `objective_id`、`canonical_fact_digest`、`oracle_fact_digest`、`risk_contribution_keys` |

关键事实：`AgentBehaviorAssessment` 随结算一起持久化（`v2_work.py:136-137` 定义在结算契约上，
`v2_campaign_store.py:79-117` 在提交结算时逐字段校验），但 `V2CampaignStore` **没有公开的结算读取方法**。

`CorpusEntry.behavior_contribution_keys` 存的是 `target_behavior_signature`，它是**单向摘要**，
无法从中恢复阶段事实。

### 结论

- 不需要修改 Finding 或 Oracle 的数据契约；
- 需要新增一个**公开只读**方法（按 Campaign 列出结算记录），与 `T03` 新增的 4 个方法同一形态；
- 因此在 `S01` 的实现区域中增加该读取方法。

### 验证方法

静态阅读；结论由 `S01` 的测试给出 `E2` 级确认。
