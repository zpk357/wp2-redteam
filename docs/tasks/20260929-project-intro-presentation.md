# 项目入门 PPT 制作任务

- 任务 ID：`PPT-20260929-INTRO`
- 标题：为项目外部技术同事制作项目入门 PPT
- 状态：`READY`
- 对应 SPEC：[20260929-project-intro-presentation.md](../specs/20260929-project-intro-presentation.md)
- 对应需求：`PPT-OBJ-01`、`PPT-SCOPE-01..06`、`PPT-COV-01..07`、`PPT-EVID-01..05`、`PPT-VIS-01..05`、`PPT-AC-01..08`

## 1. 前置依赖与被依赖项

用户已确认本任务拆解，允许进入实施。

- 前置依赖：用户批准对应 SPEC；Presentation skill 的 artifact-tool 运行环境可用；仓库现有文档与报告可读取。
- 被依赖项：无。输出 PPT 后可作为项目介绍、评审前置材料或新成员入门材料。

## 2. 包含范围

- 读取并核对产品规格、当前状态、双重覆盖机制、策略比较和已记录运行报告。
- 将内容整理为 9 到 11 页中文 PowerPoint。
- 使用流程图、双维度对照图、联合覆盖关系图、Episode 证据链图和一页小型数据图。
- 明确标注产品目标、当前实现、机制验收证据、真实运行读数和未完成边界。
- 导出 PPTX，渲染逐页检查并修正布局问题。

## 3. 不包含范围

- 不修改产品代码、覆盖算法、实验协议或数据文件。
- 不运行 Docker、真实模型、远程 Campaign 或未授权目标。
- 不新增外部数据，不把脚本模型机制验收写成真实模型效果。
- 不添加讲者备注；不制作代码教学或系统 API 参考手册。

## 4. 预计修改区域与数据流

预计新增或修改：

- `docs/tasks/20260929-project-intro-presentation.md`
- `build/` 或技能要求的私有构建目录中的 PPT 源文件和渲染产物
- 最终交付目录中的 PPTX 文件

只读内容数据流：

```text
产品规格/当前状态/运行报告
-> 事实核对与证据分层
-> 叙事大纲与页面文案
-> artifact-tool 页面对象
-> PPTX 导出
-> 渲染图逐页检查
-> 最终 PPTX
```

## 6. 验收 checklist

- [ ] 页面数量在 9 到 11 页之间，主叙事适合约 10 分钟。
- [ ] 页面不依赖代码阅读，听众可以理解 Scenario、Episode、Trace、Oracle、Coverage 和 Finding 的关系。
- [ ] 能分别解释行为覆盖、风险覆盖和联合覆盖。
- [ ] 能解释四类覆盖结果：仅新行为、仅新风险、新联合关系、无新增。
- [ ] 示例 Episode 能把真实证据、覆盖增量和下一轮反馈连起来。
- [ ] 清楚说明 `coverage_guided` 与随机基线共享测试条件，唯一原则性差异是是否消费跨 Episode 反馈；若现状存在偏差，必须显式标注。
- [ ] 真实运行读数含分母和限制，不宣称正式优越性。
- [ ] 当前能力与未完成项没有混写；Judge 置信度加固没有被宣称为完成。
- [ ] 所有页面均可读，未发现溢出、重叠、裁切、连线穿字或图表标签歧义。

## 8. 风险、失败信号与回滚

- 风险：把产品目标误写成当前能力；失败信号是页面没有证据等级或把未完成项写成已完成。
- 风险：双重覆盖被压成一个总分；失败信号是页面无法区分 B/R/J 或四类新增结果。
- 风险：真实运行读数被过度解读；失败信号是用单对小样本宣布引导优越性。
- 风险：artifact-tool 导出或字体渲染异常；失败信号是导入失败、文字溢出、图表不可读或中文缺字。
- 风险：误读现有未跟踪用户文件；处理方式是只读取已授权文档，不触碰用户已有未跟踪文件。
- 回滚：删除本任务新增的 PPT 构建产物和最终 PPTX，保留 SPEC、TASK、原始报告与用户已有文件；不修改代码或历史证据。
